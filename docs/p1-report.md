| 项目 | 当前行为 | 边界 |
| --- | --- | --- |
| 断开反馈 | 手动断开清空显示、显示断开占位；远端退出/异常/退后台保留输出，醒目标为历史；失效 token 拒绝输入和迟到输出 | 只清理手机显示，不向远端发送 exit、清屏或 kill；本地草稿保留且可编辑，发送禁用 |

| 可读 tmux 名称 | 会话名称、窗口索引/名称、pane ID；内部仍按稳定 ID 连接；名称单独读取，不参与记录分隔或命令拼接 | 当前按 session 接入；窗口/pane 列表不是独立输入焦点入口；最多 256 个 pane，每个名称展示最多 512 字符 |
| 历史阅读 | 普通 shell 手势滑动本地 scrollback，阅读时新输出不跳底，可回到最新；tmux 按 pane 获取只读文本快照，支持滑动、选区、刷新 | 本地历史上限 3000 行；tmux 快照最多 2000 行历史加屏幕，响应上限 512 KiB；快照不保留 ANSI 颜色，不是实时 TUI，也不能恢复服务器未保存的历史 |

发现并修复了无 locale SSH 的 tmux 编码问题：tmux 在此环境会将中文与制表符替换为下划线，导致名称失真及记录解析失败。调用显式加 `-u`；链接窗口的名称查询包含 session/window/pane 完整目标，避免把另一会话的名称显示过来。

## 历史阅读方案

实时终端仍使用 xterm.js；Android WebView 内部手势不再被外部 Compose 工作区抢走。终端区域的纵向手势只移动本地 viewport，不发送方向键或鼠标报告。tmux 常使用 alternate screen，本地缓冲不等于远端历史，因此提供独立 `capture-pane` 快照视图。该操作不调用 copy-mode、select-pane 或全局 set-option，不改变电脑焦点；用户在快照中选 pane 也不会改变实时输入目标。

快照请求绑定当前连接 token，请求完成时已断线/换连接则丢弃旧响应。不自动更新快照，避免阅读时跳动；点击“刷新快照”重新读取。服务端 tmux 重启后的稳定身份核验尚未完成，应在目标异常后重新发现。

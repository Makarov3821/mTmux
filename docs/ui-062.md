# 0.6.2-dev：状态灯识别与刷新延迟

## 修复原因

旧实现只检查屏幕最后 12 条非空行中的少量通用词，漏掉 Kiro 的就绪输入提示和 OpenCode 的回答耗时标记，也完全没有读取终端标题。另有两个延迟来源：每 pane 串行发多次 SSH 请求；本地过期检查用上一分钟的时间，导致新快照因“时间在未来”被错误置灰，最长等待近一分钟。

## 实现

- 参考 [Orca 标题识别](https://github.com/stablyai/orca/blob/122b8c25d7c16f76e395bf9a65887d7c4bc5003b/src/shared/agent-title-status.ts) 与 [OpenCode 标题格式](https://github.com/stablyai/orca/blob/122b8c25d7c16f76e395bf9a65887d7c4bc5003b/src/shared/opencode-terminal-title.ts)，读取 tmux `pane_title`，识别 OpenCode 原生标题/忙碌动画，以及带明确状态的 Codex/Kiro 标题。仅借鉴轻量标题规则，不移植 Orca 的完整状态系统。
- Orca 还通过 [OpenCode 插件生命周期事件](https://github.com/stablyai/orca/blob/122b8c25d7c16f76e395bf9a65887d7c4bc5003b/src/main/opencode/status-plugin-lifecycle-source.ts) 获取运行、审批和提问信号。本应用未安装此插件，也没有订阅这些事件，因此识别可靠性不能等同 Orca 的完整集成。
- Kiro 输入提示、工作中提示与审批选项依据用户提供的输出、本机 Kiro CLI 2.22.0 内置 TUI 状态分支核对；OpenCode 增加回答尾部耗时标记、当前 interrupt 控件与审批选项识别。OpenCode 当前控件也与[官方源码](https://github.com/anomalyco/opencode/blob/dev/packages/tui/src/component/prompt/index.tsx)核对。当前审批/运行信号优先于上一轮的完成标记。
- 绿色表示本轮结束或 Agent 已就绪，对应 Orca 的 idle，不能保证业务目标成功；普通 shell、只有进程名称、无输出不会据此变绿。名称/路径里的 Agent 单词不作为完成证据；shell 残留标题不判完成。
- 先读取版本和 pane IDs，再每 8 个 pane 使用一个 SSH exec 批次。别名、标题、屏幕以 Base64 分行封装，避免换行、引号造成记录混淆；仅经过验证的 IDs 与安全引用的可执行路径进入命令。
- 每 pane 前后核对 server PID、start time、session/window/pane/PID 和 dead 状态；采集失败或身份变化为未知。最多 256 pane，每屏最多 24 KiB、字段最多 2 KiB，每批有界，截断/杂音/非法记录拒绝解析。需要远端 `base64`、`head`、`tail`、`tr` 常用工具。
- 每批立即更新已收到的状态；未采集部分保持灰色。最终仅缓存名称、身份和状态枚举，不持久化屏幕正文/标题。采集不改变焦点、copy-mode，不下载全部历史、不修改远端配置。
- 新快照显色时重新取当前时间，分钟定时器仅触发过期检查。首页 30 分钟、外部进入、折叠文件夹与手动刷新规则保持不变。

## 验证

测试结果见本目录对应 evidence；使用独立 socket 的临时 OpenSSH/tmux，不访问用户现有会话。样例回放不调用模型。

- 核心测试覆盖用户两类完成画面、运行与审批优先、Orca 原生标题/动画、普通 shell 残留标题、字段封装/非法记录/身份变化、特殊字符别名、linked session、跨批次结果和 copy-mode/焦点不变。
- 10 pane / 2 session / 10 window 场景：原路径按调用结构需要 64 个 exec，新路径实际 4 个（2 个初始请求 + 2 个批次）。本地耗时仅作诊断，不作为公网/跳板延迟承诺。
- Android 回归包含“页面已打开后手动刷新，10 秒内亮绿且不重建页面”，防止分钟时钟 bug 回归。

许可证：Orca MIT 声明已加入 `THIRD_PARTY_NOTICES.md`，全文随 APK 的 `LICENSE-orca.txt` 分发。

## 仍有边界

状态灯仍是手动/既有自动刷新时的快照，不是实时监控；未把网络轮询频率改高。关闭 CLI 标题、换主题/语言、不同版本界面、任意自然语言提问或远端其他 TUI 都可能漏报/误报。用户提供的画面已做自动化回归，尚需用户实际服务器覆盖安装验证；没有宣称三种 Agent 所有版本均已实测。

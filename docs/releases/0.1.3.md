# 0.1.3：修复共享焦点导致回复误投递

2026-09-23。versionCode 7，支持覆盖安装。APK：`app/build/outputs/apk/debug/app-debug.apk`。

## 行为

连接 tmux 时绑定当时 session 的活动 pane，终端上方展示“回复目标 %…”。输入框、仅粘贴、快捷 Enter/Esc/Ctrl-C/方向键及 WebView 键盘输入均按该目标发送。电脑或手机鼠标改变焦点后，发送操作被拦截，草稿保留。切回原目标即可重新发送；要选择新目标，先清空当前草稿，再点“使用当前 pane”。不会自动搬移旧草稿。

草稿以服务器、用户名和服务/窗口/pane 身份隔离，在当前 Activity 中保存；不承诺系统杀进程后恢复。copy-mode、目标已死亡或 synchronize-panes 开启时也拒绝发送。若远端执行或连接中断导致无法确认结果，断开并提示结果不确定，不自动重放。

尺寸调整、共享显示焦点、鼠标点击/滚轮保持原有机制。本次没有引入独立手机 session，也不修改全局 tmux 配置。快捷键直接输入目标程序，不作为 tmux 前缀快捷键执行；copy-mode 使用“退出 tmux 滚动”退出。

## 投递机制

绑定记录包含 tmux 服务 PID、启动时间、session/window/pane ID 与 pane 初始进程 PID。发送时由 tmux 条件命令检查当前活动目标身份和输入状态，再明确指定目标 pane 粘贴，避免“先查询焦点，再向共享 PTY 写入”的竞态。即使检查后焦点切走，数据也不会跟着焦点换目标。pane 消失时不会回退到其他 pane。

正文经 SSH exec 的标准输入传输，使用随机命名的临时 tmux buffer；不插入 shell 参数或命令日志。成功粘贴删除 buffer，拒绝/普通错误路径通过退出清理删除。极端情况下远端 shell 被强制杀死可能遗留临时 buffer，因此不承诺异常终止时绝对零残留。`paste-buffer -r` 保留原始控制字节，包括 xterm 已编码的 bracketed paste 与回车。

服务与 pane 进程身份用于防止 ID 复用；它不识别同一 shell 内从 Codex 切换到其他命令等业务任务变化，也不是完整最近任务恢复。未实现独立显示焦点或服务器重启后的自动恢复。SSH 写入/远端投递成功不代表 Agent 执行成功。

## 验证方法

- 隔离 OpenSSH/tmux：焦点切到另一个 pane 时两边都不收到正文；切回后仅原 pane 收到中文和包含 shell 特殊字符的文本。
- 拒绝过期服务身份、copy-mode、同步输入、respawn 后复用的 pane ID、已删除的 pane、已失效连接；检查临时 buffer 清理。
- Android 15 模拟器：填写草稿后由独立 SSH 控制端切 pane，点击发送后保留草稿且两边无误投递；切回后发送成功并清空；显式绑定新 pane 后仅新目标收到。
- 原有滚动、鼠标 TUI、私钥恢复、断开与显示/输入回归继续运行。实际手机及 Codex CLI/OpenCode/Kiro CLI 兼容性仍需复测。

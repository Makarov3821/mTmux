# 0.8.2：一分钟连接保留与刷新交接

日期：2026-10-20，versionCode 30。standard / voice 保持同一 `dev.mtmux`、版本和仓库配置的发布证书。

## 行为变化

- 设置提供从左到右“无、少、中等、多、很多”：分别保留 0、1、2、3、5 条空闲 SSH 链，默认中等。修改立即生效并保存；缩容优先关闭最早入池的连接。正在使用的终端/刷新连接不计入空闲上限，跳板随同整条链一起回收。
- 成功刷新的空闲连接保留一分钟，入池停用应用心跳，借出恢复使用阶段的检测；不主动预连接，不增加状态轮询。退后台清空，零档拒绝迟到的刷新归还。服务器主动探测、关闭或密钥更新仍可能产生协议流量，不承诺网络字节绝对为零。
- 刷新中点击任务会停止派发后续状态批次，等最多两个已发出的批次结束后转交同一条已认证 SSH，再正常准备和 attach；不会把仍被状态读取线程使用的连接交给终端。等待期间可以取消；刷新失败或配置/凭据/主机信任变化时不转交。
- 列表返回时按完整目标身份、服务器和主机信任保留尚未过期的旧颜色，读完一批后只更新该批。逐 pane 保存采样时间，不因其他任务刷新而延长旧颜色的 30 分钟有效期。读取失败、新身份或过期仍灰；缓存仅保存名称、身份、状态枚举和时间。
- 日志格式仍为 diagnostics v2，构建标记为 `connection-perf-v3`；新增 `REFRESH_HANDOFF_REQUEST` / `REFRESH_HANDOFF`。详细说明见 [连接性能与日志](https://github.com/Makarov3821/mTmux/blob/v0.8.2/docs/testing/connection-performance.md)。

## 验证

- 本地 core 单元测试 31 项通过；10 项真实 loopback OpenSSH 集成通过，包括本轮新增的停止派发、排空命令和复用后不再次握手。六个涉及 PTY 的本地既有环境问题未重复计为通过，GitHub Android CI 执行完整 SSH 套件。
- standard / voice 各 6 项 app 单元测试通过；两个 debug APK 构建、两种 flavor 的 lint 和 standard Android 测试源码编译通过。新增设置与缓存 UI 回归源码只做编译验证，本地没有连接设备或可用 KVM；不将手机体验或功耗测量计为已完成。

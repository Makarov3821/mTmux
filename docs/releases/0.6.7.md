# 0.6.7：隐私展示与分级截图

2026-09-25，versionCode 24。

## 行为

设置新增“隐私展示”，默认开启，升级后未设置过的用户也默认开启。

| 场景 | 展示内容 | 截图/录屏 |
| --- | --- | --- |
| 开启隐私展示的普通页面 | 别名；没有别名则显示持久的服务器编号 | 允许 |
| 关闭隐私展示 | 用户名、地址和端口；有别名时同时显示别名 | 禁止 |
| 服务器编辑、私钥粘贴（含跳板） | 实际配置，密码/私钥默认遮罩 | 始终禁止 |
| 完整连接详情、主机指纹核对 | 实际连接字段，供核对 | 始终禁止 |

自动连接字段的隐藏覆盖首页、终端标题、移动/删除确认和发送预览。编号按服务器 ID 持久保存，不随排序、其他服务器删除或重启改变。旧版把空别名自动保存为“用户名@地址”，本版把这种生成名称视为无别名；新保存的空别名保持为空。SSH 配置、凭据加密和主机校验逻辑不变。

隐私展示不会自动修改用户别名、文件夹名、tmux 名称、搜索内容或终端输出、草稿与选区。这些内容可能自行包含地址等信息，截图前仍需自行确认。

## 实现边界

- 窗口保护由隐私开关、敏感内容作用域和前后台状态共同控制。进入保护状态立即设置 FLAG_SECURE；退出保护时等待两个动画帧，并校验策略版本，避免旧回调解除新页面的保护。
- 敏感弹窗明确使用 SecureOn，同时保护底层 Activity；用独立作用域记录嵌套保护，关闭私钥弹窗不会解除外层编辑页保护。
- Android 13+ 使用 setRecentsScreenshotEnabled(false) 禁止最近任务预览；所有版本暂停时启用 FLAG_SECURE。旧 Android 和不同厂商的任务快照时序仍需真机验证。
- 移除此前设备测试清除 FLAG_SECURE 的特殊逻辑，终端像素测试直接验证产品默认截图行为。

## 验证

专项设备测试已通过：默认开关、无别名地址隐藏、关闭后地址恢复/全局防截图、设置与编号跨 Activity 重建保留、编辑页保护、嵌套私钥 Dialog 和 Activity 均安全、关闭弹窗后外层仍安全、连接详情保护、后台与恢复策略。

Android 15 全套 30 项设备测试通过，零失败、零跳过；终端像素测试在无测试绕过的情况下通过。最终增加旧版自动别名兼容后，隐私专项再次通过，包含旧配置首页隐藏、编辑空别名保存、编号和开关持久化。最终 APK 构建与 lint 通过（0 错误，26 项警告：24 项既有项，2 项新增 SharedPreferences KTX 写法建议）。本轮没有更改终端 Web 代码。

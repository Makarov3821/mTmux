# 0.7.0：中英文界面

2026-09-26，versionCode 25。

## 行为

- 设置新增“语言”：跟随系统 / 简体中文 / English，初始为跟随系统。系统语言没有对应资源时（例如法语、日语）显示英文，英文为默认资源。
- Android 13+ 与系统“应用语言”设置联动（通过 `localeConfig` 声明 en、zh-CN）；Android 12 及以下由 AndroidX AppCompat 保存在应用私有存储。
- 切换语言会重建 Activity：重建后回到设置页，不触发首页自动刷新；SSH 交互连接按现有退后台规则断开，入口只在首页设置中。
- 不翻译用户内容：服务器别名、文件夹名、已保存的快捷回复、tmux 名称、终端输出与命令。未自定义过的默认快捷回复随界面语言显示；一旦保存即作为用户内容保留原文。

## 实现

- 约 280 条界面文本（含 3 组复数与默认快捷回复）移入 `res/values/strings.xml`（英文）与 `res/values-zh/strings.xml`，带占位符的句子整句翻译，不拼接。
- core 不再产生界面文本：错误改为 `ErrorCode`（`MtmuxException` / `InvalidInput`），连接失败为 `ConnectionFailure(hop, FailureReason)`，连接进度为 `ConnectProgress(hop, stage)`。Android 层在 `UiText.kt` 统一映射到资源。
- 终端状态从字符串改为 `TerminalStatus(text, alert)`。原先用 `status.contains("未发送"/"失败"/…)` 决定是否在已连接终端上方显示提示，改为显式 `alert` 标记，英文下行为一致。
- 修复日志阶段依赖中文：`DebugLog.stage` 过去通过匹配“准备 / 验证 / 跳板 N”编码阶段，切到英文会全部记为未知。现在直接使用结构化进度（`b = 跳板号×10 + 阶段`）；日志 `reason=` 字段改为稳定英文枚举名（如 `AUTH@hop2`、`TMUX_UNAVAILABLE`），不随界面语言变化。
- 终端网页不再输出中文提示：`validatePaste` 与连接变化提示返回固定代码（`PASTE_TOO_LONG` 等），由原生层翻译；未知代码只显示通用提示，不透传页面文本。
- `MainActivity` 改为继承 `AppCompatActivity`，主题父类改为 `Theme.AppCompat.NoActionBar`。新增依赖 `androidx.appcompat:appcompat:1.7.1`（Apache-2.0），debug APK 约增加 1–2 MB（未混淆，release 缩减后会更小）。

## 验证

- Android 15 模拟器（720×1600 / density 320，约 360dp 宽）全套 **32 项通过，0 失败、0 跳过**：原有 30 项固定在中文界面运行，新增 2 项英文测试。
  - 英文默认：首页、设置、编辑页、终端错误提示与底栏不出现未翻译的中文（语言名“简体中文”除外），任务灯无障碍描述、隐私编号“Server N”、连接失败“Target server: …”均为英文，窄屏底栏四个按钮完整显示。
  - 应用内切换到中文：重建后停留在设置页、选中“简体中文”；已到期的服务器没有因重建被刷新。切回跟随系统后恢复；设置为无资源的法语时回退到英文。
  - 日志测试新增阶段编码断言（`SSH_STAGE a=7 b=22`）和稳定 `reason=OTHER`。
- 核心与临时 OpenSSH/tmux 集成 30 项通过、0 跳过（新增错误代码测试；跳板认证失败断言改为 `hop=2 / AUTH`）；隔离 tmux 4 项通过。
- Web 单元 4 项、Chromium 页面回归通过，并新增断言：页面只发出 `CONNECTION_CHANGED`、`PASTE_MULTILINE_UNSUPPORTED` 等代码。终端资产已重新打包。
- APK 构建与 lint 通过：0 错误、28 项警告（既有依赖/KTX 建议，另有 `localeConfig` 仅 API 33+ 生效的预期提示）。
- 模拟器系统语言为 en-US，因此“英文默认”同时也是跟随系统的结果；无资源回退由法语用例单独验证。Android 12 及以下的持久化路径、TalkBack 朗读和真机厂商系统尚未验证。
- 设备测试完成后仅修改了版本号（0.7.0-dev / 25）并重新打包；之后重跑了构建、lint、core 与 Web 测试，未重跑设备测试。

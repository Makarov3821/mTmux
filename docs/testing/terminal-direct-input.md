# 终端直接输入试作

2026-10-28，本地未发布改动，基于 `d36c197`。

## 0.8.5 后续未发布调整

退格实验按用户要求暂停。`DirectTerminalInput` 的手动组合区删除算法、`TerminalDraft` 的 TextFieldState / 显式光标末尾处理，以及对应两项设备用例和两项单测都保留为注释；活动实现回到 Android BaseInputConnection 默认组合区删除和普通字符串草稿。普通终端的退格 / Delete 键转发仍属于基本输入，不增加长按计时器、加速或二次按下机制。后续实际使用再决定是否恢复这些实验处理。

0.8.5 只在字符、组词或按键事件中调用 `revealInputCursor`，唤起键盘时没有激活可见区域检查，因此键盘先遮住底部 Agent 输入区，输入后才上移。本轮在键盘唤起请求及原生焦点获得时设置 Web 输入焦点；每次 `setVisibleHeight` 更新都重新检查光标。焦点可早于或晚于键盘高度更新，键盘动画中的多次高度、保留焦点后二次打开均适用。失焦及切换连接清除焦点意图；关闭键盘恢复原偏移，不触发终端 resize，不向远端写入任何字符，不跳离本地历史。

浏览器回归新增焦点先到、键盘高度先到、动画、关闭重开、不产生远端输入、网格稳定及本地历史保护。检查结果见 [后续验证数据](../evidence/terminal-input-followup-20261028/checks.json)。以下描述保留 0.8.5 发布时的实现和验证范围，退格部分以本节当前状态为准。

## 操作

终端不再常驻本地回复框。点终端（短按，拖动不触发）或顶部键盘按钮唤起原生输入法，已确认的字符直接发送远端；回车、退格、实体键盘和一次性 Ctrl / Shift / Alt 继续可用。底部保留 48 dp 快捷键和 52 dp 辅助操作，总网格预算由 204 dp 调整为 148 dp（含顶栏）。键盘与编辑卡片不改变逻辑终端尺寸；输入光标被遮挡时只调整可见区域，浏览本地历史不强制回到底部。

语音转写完成后进入临时编辑卡片，追加录音继续加入同一草稿。顶部编辑按钮或工具中的“编辑文本”也能进入。快捷回复保持追加 / 替换确认，然后打开卡片。关闭保留当前目标的本地草稿；断线后仍能打开检查、修改，插入按钮不可用。切换连接或回复目标关闭旧卡片，不把旧文本插入新目标。

卡片只有“插入终端”，不自动回车；插入成功后清空对应草稿、收起卡片并恢复终端输入。远端已有内容由远端编辑器管理，本地不从屏幕反推完整输入框，也不提供通用的“替换远端全部文本”。多行、控制字符和字节上限沿用原有粘贴检查。

## 输入与资源

`DirectTerminalInput` 是不可见的原生 IME 端点。组合文本保存在临时 Editable，显示在 xterm 光标附近的覆盖层；提交 / 完成组词后发送一次，清空本地组合内容，不向 xterm 输出流写本地回显。旧 InputConnection 在目标变化、关闭、退后台或消费一次性修饰键后失效，不能重放字符。浮动编辑框使用 TextFieldState 保留文字、选区及组词状态；程序填入语音文字时明确把光标放到末尾，普通编辑不反复重设选区。

输入法的组合与提交语义见 [Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)，编辑状态见 [Compose TextFieldState](https://developer.android.com/develop/ui/compose/text/user-input)。

`TerminalWriteQueue` 在单个既有写线程上保持输入顺序。首个输入立即进入发送，不添加人为延时；已有网络写操作期间排队的同连接、同 epoch、同 token、同 pane、同 tmux 路径输入可合并。回调确认的粘贴、目标变化和控制回复路由保留边界。单批合并最多 8192 字节，总等待最多 65536 字节 / 64 项；断开清除等待输入，旧连接迟到失败不清除新连接的队列。

绑定 tmux pane 的输入仍使用既有原子身份 / 焦点 / copy-mode / synchronize-panes 校验和 SSH exec 粘贴。合并能减少连续输入积压时的 exec 次数，但没有引入常驻远端输入代理，也没有消除每次孤立按键的 exec 开销或网络回显 RTT。真实键入流畅度需要手机与实际网络测试。

## 长按退格

用户反馈旧常驻框第一次长按只处理最后一个标点，松手再次长按才持续删除。尚未拿到输入法名称和确切发生位置，不能认定根因，更不能宣称该反馈已被真机复现或完全修复。

本次分别覆盖：

- 本地组词删除直接编辑组合缓冲，避免 BaseInputConnection 将整个组合区视为受保护文本而跳过；缓冲清空后后续退格继续发送远端，不要求抬手。
- IME 通过连续 DELETE ACTION_DOWN / repeatCount 发送的长按，每次均处理，不用首次 KEY_UP 门槛阻断。
- 编辑卡片的文字与选区由同一 TextFieldState 管理，外部填入长语音后光标位于末尾。

这些验证不能替代用户实际输入法的按住退格手势、加速删除或滑动删除选区验证。

## 验证记录

结果写入 `docs/evidence/terminal-direct-input-20261028/checks.json`。单测覆盖队列目标 / 粘贴边界、断线隔离、容量上限，以及编辑选区和连续删除；浏览器检查覆盖本地组合预览不修改终端缓冲、字面量转义及既有滚动 / 粘贴 / 鼠标协议。

Android 用例新增 `DirectTerminalInputTest`，直接调用真实 Android BaseInputConnection，覆盖中文组合、连续退格、repeatCount、旧输入连接与一次性组合键；旧界面测试改为按需打开卡片并显式插入 / 回车。其中真实 SSH 用例增加原生直接输入、重复退格及插入不自动提交的检查。是否实际完成设备执行以验证 JSON 为准，不以编译成功代替设备通过。

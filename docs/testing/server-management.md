# 返回首页刷新、新建 tmux 会话和添加服务器验证

2026-10-28，本地未发布改动。

## 返回首页

终端返回箭头、系统返回以及远端正常退出 / detach 后回到首页，仅对刚使用的服务器跳过探测间隔；如果它所属的分组已折叠，则不发起刷新。其他服务器遵守正常自动刷新策略，自动探测间隔由 30 分钟缩短为 5 分钟，失败尝试也计入间隔。仍以最多两个服务器并发、优先领取空闲 SSH 链的方式执行。

冷启动、普通前后台切换使用 5 分钟间隔并跳过折叠分组，语言切换的原有策略保留。未在前台时的新刷新请求排队，恢复首页后执行，不在后台新开探测。

## 为服务器新开 tmux 终端

服务器卡片增加新建按钮，更多菜单也可进入。用户确认创建独立的命名会话，首个窗口使用同名，成功后直接进入新终端。创建所用 SSH 链直接交给终端，不为打开新会话再握手一次。

名称去除首尾空白，限制为 1～128 个 UTF-8 字节，不允许英文句点、冒号及控制字符。支持中文、空格等名称。Shell 引号、tmux 格式中的 `#` 和 tmux argv 的末尾分号分别进行字面量转义。

重名检查使用 `has-session -t '=完整名称'`，避免前缀或 glob 匹配误报；`new-session` 自身再原子拒绝同名，两个客户端并发时只允许一个成功。不会使用 `-A` 附着到已有会话，不会分离其他客户端。

创建回应只接受严格解析的服务器 / 会话 / 窗口 / pane 身份及窗口索引。创建超时或取消时不会盲目重试或自动删除远端资源；如果命令可能已经执行，关闭对话框后刷新列表核对。

## 保存前验证

新服务器，以及已有服务器的地址、路由或认证信息变更，会先连接完整 SSH / Jump Host 路由。别名、分组、鼠标设置或 tmux 路径等本地修改不额外要求一次登录验证。

未知指纹在同一次 SSH 握手中等待用户明确确认，确认后继续认证。已知指纹变化始终拒绝，不提供覆盖信任。跳板按顺序分别确认；临时确认只保存在当前编辑流程内，重试可复用，离开编辑器即丢弃。

认证成功后才加密保存配置、提交用户已确认的指纹，并将有效 SSH 链归还原有空闲池。返回首页后使用该链刷新；不需要先单独进入终端才能确认指纹。保存检查验证 SSH 身份和登录，不要求目标已经安装 tmux，保留 SSH-only 服务器的用途。

失败时保持草稿、显示本地化原因，可重新验证、返回修改或点“仍然保存（Save anyway）”。强制保存只保存加密配置，不提交本次临时指纹、不立即自动再连接；首页显示未验证状态，清除旧状态颜色。服务器菜单的“验证指纹”、原有指纹提示及终端首次连接的验证入口均保留。

取消和退后台会解除指纹等待、取消连接，不能在 Compose 尚未销毁协程的短窗口里继续提交保存。一旦短暂的本地提交已开始，会完成提交与导航，避免留下半个编辑流程。

## 验证

自动化覆盖：

- 未知指纹确认只建立一次 TCP 连接，继续 SSH 认证及 exec。
- 指纹确认等待超过 15 秒仍能继续认证。
- 确认指纹后错误密码被归类为认证失败，不误报为未知主机。
- 已知键变化不会触发“接受未知键”回调；等待确认期间信任记录改变时拒绝旧键。
- 临时 Jump Host / 目标指纹不写入持久信任。
- 新会话中文名、前缀、`#{…}`、引号、命令替换及末尾分号均保持字面含义。
- 精确重名与并发创建（一个成功、一个重名），新 pane 身份可用于后续绑定。
- 关闭编辑器会解除指纹等待；取消标记能阻止迟到的提交。
- 保存策略区分本地展示修改、目标变更和跳板认证变更。
- 返回时跳过时间间隔仍受折叠分组限制；其他服务器保持正常策略；自动间隔在 5 分钟边界到期，并处理系统时钟回拨。

完整 SSH 集成使用 `scripts/test_ssh.py --probe-pty` 的临时 loopback sshd、临时密钥和独立 tmux socket，不修改用户的 authorized_keys 或默认 tmux 服务。沙箱内 PTY 探测失败；在获准的沙箱外执行中，PTY 检查及完整集成通过。

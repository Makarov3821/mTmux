# SRF 过度断句：保守过滤

2026-10-25，基于 0.8.5-rc.2 的本地未发布修改。现有 rc.2 APK 不包含本页调整。

## 原因与范围

原实现直接选分数最高的标点类别。SRF 在“然后修改代码修改完成后运行测试”的一个位置，对“逗号”和“不加标点”的 softmax 归一化分数约为 0.501 / 0.480，仍插入了“修改，完成”的逗号。另有句中问号把“什么原因造成的”提前断开。

这些归一化分数不是经过校准的准确率，不能当作真实正确概率。单独输入“有的时候会多加标点”没有复现句中的逗号；用户实际输入的完整上下文仍待补充。多余标点也可能已经存在于 Whisper 原文，不能把全部问题归因于 SRF。

## 调整

只对 SRF 的**新增句中标点**应用过滤：

- “不加标点”的归一化分数高于 0.10 时，保留原文，不插入该位置预测的标点。
- 句中的句号、问号、感叹号，胜出标签分数还需达到 0.97，减少提前结束一句话。
- 末尾位置仍沿用原有处理；整段文本的末尾才算末尾，不把重叠窗口的尾部当作句末。
- CT 仍沿用原选择逻辑。已有标点、原文字和空格的保留规则不变；过滤不会纠正错字、删除 Whisper 原有的标点，也不重写技术片段。

`PunctuationPrediction` 直接读取已有模型 logits，以稳定 softmax 计算分数，没有引入新模型或额外推理。该组阈值是保守的工程起点，不是经独立测试集优化出的最佳值。

过滤也会去掉一些正确停顿，例如“如果连接失败，就回到主界面，并保留错误日志”中的后一处逗号。这是偏向少加标点的取舍，不能仅凭五条样例宣称整体准确率提升；仍需要实际长句、短句和技术指令测试。记录是桌面模型输出，不代替 Android 全流程或手机时延验证。

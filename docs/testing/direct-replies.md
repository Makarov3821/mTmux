# 快捷回复与语音编辑发送验证

2026-11-02，基于 `a21fd17` 的工作区改动。设计见 [发送交互](../design/direct-replies.md)。

## 范围

- 快捷回复使用真实 SSH shell，通过拆分的 printf 标记验证点击一次确实执行一次，排除仅回显文本的假通过。
- 本地草稿刻意使用与快捷回复相同的文字，验证发送回调不清空；保存修改后的回复再点击，验证编辑仍可用；断线后再点击不产生输入。
- 绑定 tmux pane 使用关闭回显的 cat，只有实际收到 Enter 才产生标记；电脑切换 pane 后拒绝写入，切回后需再次点击才提交，不会重放。
- 语音设置验证默认开启、关闭后持久化、Activity 重建后的恢复、重新开启，以及 standard 隐藏。
- 原有直接输入、手动编辑插入、目标改变、断线重连和不重放输入回归。
- 语音录音/转写原有用例检查不在识别完成时直接提交；本次交互保留用户点击编辑卡片按钮的步骤。

## 当前结果

两版 Debug、测试 APK、app JVM 各 50 项及 lint 通过。两 APK 固定模型与运行库校验、无旧语音负载检查通过。

Android 逐项检查通过：standard 6 项、voice 7 项，共 13 项，0 失败、0 跳过。模拟器使用专用 `mtmux-test`，API 35 / x86_64，WebView 124。首轮 11 项验证后，仅向测试文件补充 pane 用例与导入，生产代码未再修改；补充 2 项分别在两版通过。

日志与 XML 位于 `.tools/diagnostics/direct-replies/` 和 `.tools/diagnostics/matrix/direct-replies-*/`。首轮和补充轮各自核对测试选择、runner 状态、XML 数量及源码哈希；新增 pane 用例初次编译缺少导入，补齐后测试 APK 与 lint 通过，原编译日志保留在 `build-bound.log`，修正后为 `build-bound-round2.log`。

真实语音内容、手机输入法与远端 Agent 的发送效果仍以实际设备使用为准，不把静音录音用例当成语音发送全过程验收。

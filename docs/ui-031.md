# 0.3.1：修复设备属性回复漏入远端输入区

2026-09-24，versionCode 12。

## 原因与修复

用户看到的 `0;276;0c` 来自完整终端回复 `ESC [ > 0 ; 276 ; 0 c`。本地固定版本 xterm.js 的 `src/common/InputHandler.ts` 中 `sendDeviceAttributesSecondary` 在收到 DA2 查询时发送此内容。

xterm 的 `onData` 同时承载用户按键和自动协议回复。此前 Android 桥接只把鼠标事件送入 attach 的 SSH PTY，其他内容一律经过 `sendToPane`/`paste-buffer`。因此 tmux 的客户端能力回复被错误地投到 pane 内程序，控制字符可能被程序消耗，留下可见的数字串；它不属于手机 Compose 回复框，所以无法通过编辑手机草稿删除。

新增完整 DA1/DA2 回复识别，直接返回当前 SSH PTY，由 tmux 客户端协议层处理。严格匹配整条序列并限制长度；附加文本、不完整序列、方向键、快捷键和普通草稿仍走原路，继续执行 pane 目标校验。没有屏蔽能力查询或关闭终端协议。

本次修复范围为设备属性回复（DA1/DA2），不把所有 ESC 序列都当成协议流。已混入远端编辑区的文本不会自动删除，避免误删用户草稿；可在电脑同一 pane 中手动删除。

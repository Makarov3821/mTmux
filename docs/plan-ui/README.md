## 方案 A 第二版：交互细化（当前方向）

按反馈继续方案 A，B 和 C 不再推进。第二版共 17 个界面：[展板](png/a2-refined-board.png) · [HTML](a2-refined.html) · [单屏 PNG](png/a2-refined/)。第一版中认可的编辑服务器（[03](png/a-refined/03-server-edit.png)）、连接阶段卡和设置页（[11](png/a-refined/11-settings.png)）保持不变，第二版沿用其样式。

| 界面 | 改动 |
| --- | --- |
| 01 首页 | “服务器”大标题换成 56dp 应用栏（小图标 + mtmux）；等待回复和运行中的数量改成顶部小标签；任务行只保留色点、会话名、窗口序号，去掉 pane 行和“已就绪”等状态文字，需回复的色点外加一圈细环。卡片右侧从左到右为 SSH 终端（强调色）、新建会话、刷新、⋮，前三个常驻，⋮ 只放低频操作 |
| 02 服务器操作 | ⋮ 或长按从底部升起圆角操作面板（tmux Doctor、编辑、查看主机指纹、移动分组、删除），替代贴着按钮的下拉菜单；被操作的卡片描边，删除单独分隔 |
| 03 刷新与保存反馈 | 刷新进度是卡片顶边的渐变线，刷新键变为转圈；刷新失败只改副标题，刷新键变红；新服务器短暂描边并带“新”标签 |
| 04–06 添加服务器 | 保存时从底部升起验证面板（阶段卡 + 路线标签）；首次指纹核对移到这里，标明“第 2 / 2 台”；验证失败给出失败的一级，“重新验证”为主操作，“仍然保存”降为第三选项 |
| 07 终端 | 底栏改成顶部圆角的面板；顶栏副标题去掉 pane 编号。沿用 0.8.5 的直接输入，没有独立输入框，图中最后一行 `›` 是远端 Agent 自己的提示行，光标处即输入位置 |
| 08–09 连接中 / 认证失败 | 第一版阶段卡改为半透明浮动卡片；失败时同一张卡原位切换内容 |
| 10–11 断线 | 红框浮层改为底栏上方的小卡片，只有图标、断开原因和“重连”；不重连就直接返回首页。向上滚动查看历史时收起为顶部胶囊，也只有“重连” |
| 12–15 语音 | 参考微信：按住后下半屏渐暗，底部升起弧形按压区，气泡显示实时音量和剩余时间。手指向任意方向上移、离开弧形区即进入取消态：气泡变红带 ×，弧形区下沉，提示“松开 取消”，移回即恢复；没有单独的取消按钮。最后 10 秒气泡变橙并显示大号倒计时。松手后转写，结果填入编辑卡片的文本框，不自动发送 |
| 16 编辑卡片 + 键盘 | 键盘弹出时卡片收紧为三行：标题行（目标、关闭）、输入框、录音和“插入终端” |
| 17 语音错误 | “录音太短”等错误改为语音按钮上方 2–3 秒自动消失的提示；只有缺少麦克风权限时才弹出面板 |

实现备注：

- 多 pane 不在这一阶段的支持范围内，首页不显示 pane 行。
- 语音取消的判定是“手指离开弧形按压区的上边缘”，与水平方向无关。
- 弧形区升起与下沉、气泡变色、断线卡片与胶囊的切换都需要动画（约 150–200 ms），静态图里看不出来。

### 0.9 新增界面：tmux Doctor

对应图集里新增的 `doctor/` 7 张图，以及首页“tmux 不可用”状态、服务器菜单的 Doctor 入口和新建会话前的快速检查。共 9 个界面：[展板](png/a2-doctor-board.png) · [HTML](a2-doctor.html) · [单屏 PNG](png/a2-doctor/)。

现状的问题：全部是默认 AlertDialog。报告是 13 行“✓ / ⚠ 标题 + 说明 + 原始值”的长列表，正常项和问题项一样醒目，要滚动才能找到问题；“预览最小配置”“复制建议”“撤销”“继续新建会话”作为文字按钮混在正文里；邀请弹窗出现在首页上方，和刚完成的保存操作断开。

| 界面 | 改动 |
| --- | --- |
| D1 保存后邀请 | 验证面板直接转为成功态，Doctor 邀请作为面板里的一张卡；跳过即回首页 |
| D2 检查中 | 沿用连接阶段卡的逐项打勾样式，顶部圆环显示完成项数 |
| D3 诊断报告 | 顶部一句结论（可以使用 / 不能使用 + 建议数）；需要注意的项展开，正常项收成两列小标签；“复制配置建议 / 重新检查”固定在底部 |
| D4 未安装 tmux | 只讲这一件事：有备选路径就给“改用此路径”，否则列出可复制的 apt / dnf / apk 安装命令；后续项合并为“未检查” |
| D5 最小配置预览 | 配置以带文件名、行号、高亮的代码块展示；历史行数改为常用档位 + 自定义；确认勾选放进卡片，未勾选时主按钮不可点 |
| D6 创建成功 | 给出下一步“新建会话”；撤销作为红色文字按钮留在同一面板 |

| D9 新建会话 | 改为贴着键盘的底部面板；创建前的快速检查缩成标题下一行结果，失败时变红并给“打开 Doctor” |

## 现状的主要问题

浏览截图后，问题集中在“连接、提示、弹窗”，首页和终端主体的方向没有问题。

1. **连接和错误状态没有固定位置。** 连接中是终端顶部一条浮层（`目标服务器：正在连接…`），正文中间再放一句“请查看上方进度”；认证失败、断线、pane 拦截都是同一个红边浮层，盖住终端前两行输出。用户看不出卡在哪一级、该做什么。
2. **错误后的操作不匹配原因。** 认证失败时给的是“重连最近任务 / 重新选择任务”，而用户真正需要的是“编辑服务器 / 重试”。
3. **弹窗是默认 Material AlertDialog。** 标题、说明、指纹挤成一段文字；指纹没有分组，难以逐段比对；首次信任和密钥变化只差一个图标颜色。
4. **首页卡片操作太多。** 每台服务器一行放 `>_`、`＋`、刷新、`⋮` 四个同权重按钮，名称只剩一半宽度；刷新时间以小字挂在名称下方。
5. **状态只靠一个小圆点。** 红黄绿灰没有文字，过期和未知也无法区分；“上次使用”是蓝色文字，比状态更显眼。
6. **强调色用得太多。** 设置的每个分组标题、所有文字按钮、开关都是强调蓝，主操作反而不突出；设置页每项都有两三行说明。
7. **细节不统一。** 终端四周有一圈和背景不同的边框；描边输入框和填充卡片混用；空状态、校验错误、语音错误各用一套写法。

三套方案都解决上面七点，差别在视觉语言。

## 方案 A：精修现状

保留现在的深色、圆角卡片和终端优先结构，按“执行问题”逐项修。

- 服务器卡片只留 SSH 和更多两个按钮；刷新时间作为元信息，新建会话移到空列表里。
- 任务行：色点 + 状态文字胶囊（需回复 / 运行中 / 已就绪 / 已过期）；多 pane 用缩进引导线。
- 指纹待确认、刷新失败用卡片内提示条，和任务状态分开；操作结果用底部提示。
- 连接中、认证失败使用终端区中央的同一张步骤卡：每级跳板、认证、tmux 核对逐行打勾并显示耗时，失败时标出失败的那一级，按钮改为“编辑服务器 / 重试”。
- 断线提示条占据顶栏下方独立一行，不再覆盖输出。
- 弹窗统一为“图标 → 标题 → 关键数据块 → 主按钮 → 次按钮”；指纹按 4 字符分组，带复制。
- 输入框改填充式；设置的分组标题改灰，说明压缩为一行。

**适合**：想尽快上线、不想重新学习。色板、圆角、组件都能沿用 `AppAppearance.kt` 里的六套主题，工作量最小。

## 方案 B：终端原生

把应用当成 tmux 的延伸：全局等宽、直角、1px 线框，没有阴影。

- 首页像 `tmux ls` 的树形输出，顶部一行汇总四种状态数量，底部是 tmux 风格的状态栏。
- 服务器编辑和设置都用“键 · 值”行，跳板链直接写成 `phone → jump-1 → target`。
- 连接过程像 init 日志逐行打印 `[ ok ]`、耗时，失败停在 `[FAIL]` 那一行。
- 终端下方复刻 tmux 状态栏（会话、窗口、pane、行列、快捷键页码）；键帽和底部操作是等分网格，语音占中间整格。
- 指纹和错误用 `[?]` / `[!!]` 前缀的线框弹窗；密钥变化列出新旧摘要。

**适合**：目标用户就是重度终端用户，追求信息密度，同样的屏幕能放下更多任务行。缺点是对新手不友好，全等宽中文段落读起来偏累，需要重新做一套组件。

## 方案 C：安静纸面

面向“离开电脑后看一眼、回一句”的场景，读起来像一份进度报告。

- 暖白纸色、衬线标题、墨黑主按钮，用细线和留白分层，几乎不用卡片底色。
- 首页标题下一句话汇总：“1 个任务在等你回复，2 个运行中。”任务行左侧色条 + 右侧状态文字。
- 提示用左侧粗线的旁注：黑线需要你确认，红线是出错。
- 指纹弹窗标题写成问题“这台服务器的指纹和你知道的一致吗？”，并给出核对命令。
- 连接、失败使用整页编号清单，失败页写清“第 3 步失败、跳板不用改”。
- 编辑卡片标题是“写给 code-review”，输入区像信纸，只有一条底线。
- 终端也是浅色纸面；夜间需要再配一套深色“墨纸”版。

**适合**：希望和其他终端 App 拉开差异，或用户多在白天户外、通勤时查看。风险是 ANSI 颜色在浅底上需要重新调对比度，部分 Agent TUI 默认按深色背景设计。

## 对比

| --- | --- | --- | --- |
| 和现在的差异 | 小 | 大 | 大 |

## 落地建议

我建议以 A 为基础，因为它最贴近你说的“精神对、执行不到位”。另外从 B 和 C 各借一处：

1. **从 B 借连接日志**：连接中 / 失败页显示每一步的结果和耗时。数据已经在连接性能日志（`connection-perf-v3`）里，只需要转成界面状态。
2. **从 C 借一句话汇总和失败结论**：首页标题下写“1 个任务在等你回复”；失败页写清哪一步失败、该改什么、什么不用改。

建议先做的改动按收益排序：

1. 连接 / 认证失败 / 断线三种状态改成固定位置的步骤卡和提示条，替换现有浮层；认证失败的主按钮改为“编辑服务器 / 重试”。
2. 主机指纹弹窗重排：分级标注、指纹分组、首次信任和密钥变化使用两种明显不同的版式。
3. 首页服务器卡片减少到两个操作按钮，状态点加文字。
4. 设置页去掉分组标题的强调色，说明压缩为一行。

这些改动不涉及终端逻辑网格或底栏高度（仍为 156 dp），不影响远端 resize 与键盘避让。

## 文件与重新渲染

```text
docs/plan-ui/
  a-refined.html  b-tui.html  c-paper.html   三套方案的源文件，可直接用浏览器打开
  a2-refined.html     方案 A 第二版（shared/a2.css）
  a2-doctor.html      方案 A 第二版 · tmux Doctor 与 0.9 新增界面
  shared/icons.js     线性图标
  shared/term.js      演示终端内容
  shared/board.css    展板与手机外框
  shared/{a,b,c}.css  各方案样式
  shared/render.mjs   渲染脚本
  shared/compare.py   拼接对比图
  png/                渲染结果（单屏 720×1600、展板、对比图）
```

渲染需要 `web/node_modules` 里的 `playwright-core` 和本机 Chrome（可用 `CHROME_BIN` 指定）：

```bash
node docs/plan-ui/shared/render.mjs            # 全部
node docs/plan-ui/shared/render.mjs b-tui      # 只渲染一套
```

字体使用本机的 Ubuntu Sans / Ubuntu Sans Mono / Noto Sans CJK / Noto Serif CJK。Android 上方案 C 的衬线标题需要打包字体（Noto Serif SC 子集约 1–2 MB），或改用系统衬线字体。对比图 `png/compare.png` 由 `python3 docs/plan-ui/shared/compare.py` 拼接（需要 Pillow），修改后需重新运行。

# 0.1.4：最近任务入口与安全重连

2026-09-24。versionCode 8，可覆盖安装。APK：`app/build/outputs/apk/debug/app-debug.apk`。

## 使用流程

成功进入任务后保存最近记录，最多 10 条。旧版没有保存任务身份，升级后需正常连接一次开始记录。配置页顶部显示服务器、session/window 名称和 pane；点击一次便使用已保存凭据核对目标并连接。断线或退后台返回后，终端页提供“重连最近任务”和“重新选择任务”。不在启动、返回前台或网络恢复时自动建立连接，不自动重试认证。

重连前继续执行主机密钥校验，并核对原来保存的主机信任记录。服务器配置的地址、端口、用户名和 tmux 路径必须一致。远端检查服务 PID/启动时间、session/window/pane ID、pane 初始进程 PID 和存活状态；检查通过后，带条件的 attach 命令再次核对，并切回原窗口/pane。此操作会改变电脑共享焦点，不会踢掉电脑客户端；尺寸仍共享。

原 pane 关闭、移动、respawn、tmux 重启或 ID 复用时拒绝恢复，不按名称寻找替代任务；失败保留原记录和未提交草稿。点“重新选择任务”重新发现，用户明确选择后才能进入新任务。普通 shell 条目明确标为“新连接”，不承诺恢复旧 shell 进程。

## 本机记录与输入

最近任务仅保存配置引用、目标身份、显示名称、主机公钥和访问时间；密码/私钥仍引用已有加密存储，不重复保存，终端输出与草稿不落盘。重启 App 后任务入口仍可用；当前 Activity 中的草稿按目标身份保留，但不承诺进程重启后恢复草稿。

手动连接、最近任务恢复和显式“使用当前 pane”成功后更新记录。失败连接不更新访问记录。改变服务器地址/端口/用户名/tmux 路径会删除对应记录，改显示名称保留；删除配置同时删除任务入口。明确进入重建后的 pane 后替换同 pane 旧记录；明确连接新 tmux 服务后清理该配置的旧服务记录，避免同名重复入口。

重连生成新的连接代际，旧输入队列和旧 WebView token 不能进入新连接。保留的草稿只恢复到输入框，不自动粘贴或发送 Enter。投递结果不确定时仍提示检查远端，不自动重放。

## 验证范围

- 核心 SSH/tmux：当前窗口已切走时恢复原窗口/pane，期间没有输入；关闭或 respawn 后拒绝恢复。
- 独立 tmux 服务真实 kill/restart，创建同名 session 且 session/pane ID 相同：旧身份被拒绝，新身份可核对。
- Android 15 模拟器：重建 Activity 后最近入口可用；后台停止/返回不自动连接，手动重连回到原目标且草稿未投递；旧 token 输入被拒绝。
- 主机信任记录变化阻止最近任务恢复；respawn 后显示拒绝，旧记录不覆盖；重新发现并明确选择后才能连接新任务。
- 存储测试：10 条上限、同 pane 记录替换、新服务旧记录清理、改名保留、连接参数改变及删除配置清理；记录不包含测试密码。
- 原有滚动、鼠标、回复目标、配置/凭据、断开与终端显示继续回归。截图与结果见 [证据目录](evidence/p1-014/README.md)。

本次不是自动后台重连服务；网络切换的具体时机、真实手机及各 Agent 仍需按清单验证。身份绑定的是 tmux pane 的生命周期，不识别同一个 shell 内启动了另一个 Agent 等业务变化。

按用户本次优先级调整，下一阶段集中优化展示逻辑和 UI；其他扩展功能暂缓。

最终结果：14 项核心/SSH 测试、13 项 Android 全量回归通过，无跳过。记录去重及旧服务清理调整后，两项存储/恢复回归再次通过；APK 编译与 Android lint 通过。

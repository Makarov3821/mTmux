# mtmux UI 设计：服务器与终端

2026-09-24。设计草案；已按本方案实现 0.2.0，见 [实现与验证](ui-020.md)。首页和服务器配置已实现；终端新布局与键盘滚动保持方案见第 5 节，实现记录见 [0.3.0](ui-030.md)。多级 Jump Host 按用户最新需求纳入本轮范围，取代旧计划的跳板机暂缓决定。

示意图：[四界面总览](ui/ui-overview-v1.png) · [可在浏览器放大的 HTML](ui/ui-overview-v1.html)。第三屏表示服务器表单滚动到高级选项后的状态。

## 1. 首页：服务器单列列表

应用启动直接进入首页。顶部标题“服务器”，右上角依次放设置与添加按钮。使用普通列表、细分隔线、清晰缩进；避免大型卡片、仪表盘和首页表单。

```text
服务器                         ⚙   ＋

⌄ 家里的服务器            >_   ⟳   ⋮
  zyl@home.example.com
  刚刚更新
    agent / codex                  ›
    dev / backend                  ›
────────────────────────────────────
⌄ 工作服务器              >_   ⟳   ⋮
  dev@10.0.0.8 · 经 2 级跳板
  刷新失败 · 显示上次缓存
    work / opencode                ›
```

- 服务器名称优先用别名，有别名时隐藏用户名和地址；无别名显示用户名/地址。更新时间与名称同行。服务器默认展开，点名称可以折叠；折叠状态本机保存。
- 子项显示上次发现的 tmux 终端，主文字为“会话名 / 窗口名”。单 pane 窗口直接进入；多 pane 窗口展开简短子列表后选择具体 pane，避免随机进入。内部 ID 不作主标题，重名时辅助显示窗口索引/pane 编号。
- 最近使用的子项加小型“上次使用”标记，不再单独放一份最近任务列表。子列表只展示 tmux 终端。
- 服务器右侧依次放普通 SSH 小按钮（终端图标 `>_`）、刷新、更多菜单。SSH 按钮直接打开该服务器的普通 shell，沿用配置的跳板链；不要求先发现 tmux。折叠服务器后按钮仍可用，提供“打开 SSH 终端”的无障碍标签和长按提示。
- 右侧刷新按钮只刷新这台服务器；刷新时按钮显示进度，不改变列表位置。更多菜单提供“编辑服务器”“删除服务器”。
- 没有服务器时显示一句“添加服务器，连接你的终端”和添加按钮；服务器没有 tmux 会话时显示“暂无 tmux 会话”，仍保留普通 SSH 入口。

### 缓存与刷新

- 缓存的是上次成功发现的会话/窗口/pane 列表、身份信息和刷新时间，不是终端输出；与目前只保存最近访问任务不同，需要新增列表缓存。
- 冷启动或 App 从后台回到首页时，立即显示缓存，对展开文件夹及未分组中距离上次嗅探至少 30 分钟的服务器自动刷新；首次无记录立即嗅探。使用已保存凭据；限制并发、合并同一服务器的重复请求，不因界面重绘重复刷新。
- 刷新成功替换该服务器缓存；成功但无会话显示空状态。刷新失败保留缓存并标记失败/更新时间，不能把网络错误当作“没有会话”。
- 自动刷新遇到首次主机验证或凭据缺失，在对应行提示“需确认指纹”或“需补充凭据”，用户点该行处理，不连续弹出多个窗口；主机密钥变化继续拦截。
- 点击缓存子项时，仍核对任务身份后连接。任务已关闭、重建或移动时提示，由用户手动刷新重新选择，不能按同名记录静默进入其他任务。
- 新增/编辑保存返回首页不触发自动刷新，可使用手动刷新；修改连接地址、账号、tmux 路径或跳板链后，旧目标缓存及最近记录失效。失败刷新不妨碍用户操作其他服务器。

## 2. 添加 / 编辑服务器窗口

点右上角 ＋，打开独立全屏表单窗口；编辑复用同一窗口并回填数据。手机采用全屏以容纳键盘和多级跳板，顶部固定取消与保存。设置按钮打开独立设置页，放字号、滚动速度等全局偏好，不进入添加服务器流程。

```text
取消          添加服务器          保存

别名          家里的服务器
地址          IP 或域名
端口          22
用户名        zyl

认证方式      私钥 ▾
私钥文件      选择文件 / 已导入
私钥口令      可选                 ◉

⌄ 高级选项（默认折叠）
  Jump Host   关闭 / 开启
    手机 → 跳板 1 → 跳板 2 → 目标服务器

    跳板 1                       删除
    地址 / 端口 / 用户名
    认证方式 / 私钥或密码 / 私钥口令

    跳板 2                    上移 删除
    地址 / 端口 / 用户名
    认证方式 / 私钥或密码 / 私钥口令

    ＋ 添加一级跳板

  tmux 路径、连接时开启鼠标
```

- 默认端口 22；别名留空时以“用户名@地址”展示。地址、端口、用户名必填。
- 认证方式为密码或私钥，选择后只显示相关字段。敏感输入默认遮挡，允许点按显示；编辑时显示“已保存”，无需重复导入，也不展示私钥正文。
- Jump Host 放在默认折叠的“高级选项”中，默认关闭；已有跳板配置时，高级选项标题附“已配置 N 级跳板”摘要，折叠不会禁用配置。开启后可添加多级跳板，各级分别填写地址、端口、用户名和认证信息，支持删除及上移/下移。顺序明确为手机 → 第一级 → 后续各级 → 目标服务器；每级可使用不同认证方式。
- 跳板块支持折叠，折叠后显示用户名和地址，减少长表单的滚动负担。链路中的每个跳板和最终服务器都分别确认主机身份、保存本机凭据。
- 保存只做表单校验与本机保存，不以服务器在线作为保存前提。成功后关闭窗口回到首页，新增/更新对应服务器并开始刷新；错误在字段附近显示，输入不丢失。
- 取消/系统返回直接关闭未改动表单；已修改时询问是否放弃。删除服务器只删除本机配置、凭据和缓存，不操作远端任务。

## 3. 页面衔接

首页 → 点击终端子项 → 终端页；返回首页关闭手机当前交互连接，保留未提交草稿和最近目标，并显示首页缓存，不自动刷新。发现列表的连接不接管交互终端，不改电脑焦点；真正进入/恢复目标时沿用现有目标校验与共享尺寸规则。

首页 → 服务器右侧 SSH 小按钮 → 普通 shell（使用该服务器完整连接配置，包括跳板链）。

首页 → ＋ / 编辑 → 服务器表单 → 保存 → 首页自动刷新。

首页 → 设置 → 全局偏好 → 返回首页显示缓存，不自动刷新。

## 4. 实施边界与验收

本轮 UI 改造需要配套实现列表缓存和自动刷新；多级 SSH 跳板还需要连接层能力，不能只添加字段后宣称支持。连接链用于发现、终端连接、目标核对和重连的全部路径；中间某一级失败应指出失败级别，不能静默绕过跳板直连。SSH config 导入仍暂缓。

验收重点：启动先看到缓存；外部进入首页按 30 分钟及文件夹状态刷新，内部返回只显示缓存且不闪空；单台手动刷新不影响其他行；离线仍能保存配置；窗口保存后关闭；编辑/删除不遗留旧任务；多级跳板顺序、不同认证及各级错误提示正确；点击缓存旧任务仍有防误连接保护。

建议顺序：先完成首页与表单的静态交互，再接缓存刷新和已有直连能力，最后接入多级跳板并贯通发现/连接/重连测试。正式交付前完整验证全部约定行为。下一轮再单独调整终端内部 UI。

## 0.2.1 首页调整（2026-09-24）

本节覆盖上文“每次返回立即刷新”和显示地址副标题的旧设计：按 0.4.1 更新规则：冷启动或从后台回到首页时，仅展开文件夹和未分组参与自动刷新，每台服务器距离上次嗅探至少 30 分钟才自动刷新；首次无记录立即嗅探，失败尝试也计入间隔，记录跨重启保留。手动刷新和确认指纹后的继续连接不受间隔限制，修改连接目标使旧间隔失效。不增加后台定时嗅探。

有别名时不显示用户名与地址；无别名使用用户名/地址作为名称。更新时间放在名称旁，正常状态没有单独的更新时间行。长名称单行省略，SSH/刷新/更多按钮保持可用；错误及指纹确认提示保留。下一步增加可选文件夹分组，详见主计划。

## 5. 终端页改版（2026-09-24）

效果图：[终端双状态预览](ui/terminal-v2.png) · [HTML 原稿](ui/terminal-v2.html)。下文保留设计与验收要求；0.3.0 的最终实现和实测结果见 [交付记录](ui-030.md)。

### 布局

- 延续深绿黑底与低饱和绿色点缀，终端和页面使用同一背景，移除终端四周描边、卡片感及阴影。屏幕左右保留约 12dp 内容间距，遵守系统安全区，尽量让终端占满剩余空间。
- 顶部只有一行，约 48dp：`‹  服务器别名 · 会话 / 窗口                  ⇣`。最左返回首页，关闭手机当前交互连接，不结束远端 tmux 任务；中间显示当前服务器和 tmux 会话/窗口名称。有别名只显示别名，无别名显示用户名@地址（非默认端口附加端口）；普通 shell 显示 `SSH`。长标题单行省略，点击标题可查看完整连接/目标信息。
- 顶部右侧仅保留“回到底端”图标，提供同名无障碍标签。移除“终端”标题、断开按钮、顶部收起键盘按钮及常驻连接诊断/回复目标行。
- 终端下方紧接快捷键分页栏：第 1 页 `Esc  Tab  Ctrl-C  ↑  ↓  Enter`，第 2 页 F1–F6，第 3 页 F7–F12。每页六键等宽铺满，左右滑动整页切换，底部三个小圆点提示当前页。取消“历史快照”“退出滚动”入口，不再有独立历史操作行。
- 功能键下方是回复框，使用轻微底色和圆角，不使用强对比描边；空白提示“输入命令或回复…”。固定紧凑高度，显示约 2 行后内部滚动，草稿保留现有目标隔离。
- 最底部一行固定为：左“工具”、中“收起键盘”、右主按钮“发送回车”。键盘隐藏时中间按钮置为弱色禁用，位置不移动；输入法出现后整组输入控件停靠在键盘上方。发送沿用现有多行预览与目标校验；“仅粘贴”移入工具。
- 工具以底部面板承载字号、滚动偏好、复制选区、仅粘贴和回复目标/显式重新绑定。正常状态不显示技术 ID；目标变化、断线或发送失败时提供紧凑且可操作的临时提示，禁发、保留草稿和安全重连不因精简界面而移除。

### “回到底端”的行为

普通 shell 回到本机终端底端；tmux 正处于 copy-mode 时，只针对当前显示且已核对的 pane 退出 copy-mode，再回到底端。无需用户理解“退出滚动”术语。不得对不相关 pane 发送控制键，也不使用通用 Esc/Ctrl-C 强行退出 Agent。Agent 自己内部的历史状态没有统一协议，本按钮不承诺能把任意 Agent 内部视图跳到最新。

### 键盘切换不改变阅读位置（本轮重点 bug）

用户反馈：点击回复框或收起键盘时，终端像从头滚动一遍。验收目标是**在没有新输出时，键盘弹出/收起前后当前顶部几行及其相对位置保持不变**；阅读历史时不能自动跳到底端。到达末尾且用户没有离开底部时，正常的新输出跟随行为保留；点击回复框、失焦、收起键盘本身不触发回到底端。发送后也不额外滚回工作区顶部。

代码初查（尚非真机根因结论）：

- Compose 外层为 `verticalScroll + minimumWorkspaceHeight(500dp)`，配合 `imePadding`，可能在获得焦点时滚动整个工作区。
- Web 侧 `ResizeObserver → fit.fit()` 将高度变化转成 PTY resize，tmux/TUI 可能因此重绘；当前没有在键盘过渡时保持阅读锚点。
- 发送成功后还存在 `workspaceScroll.animateScrollTo(0)`，是明确的主动滚动，应移除。

实施方案：

1. 固定顶部与底部控件，终端拥有独立视口，移除整页可滚动的工作区；回复框焦点不应驱动终端滚动。不销毁或重新创建 WebView/xterm，不重置终端缓存。
2. 将 IME 可视区域变化与真正终端网格尺寸变化区分。优先验证键盘动画期间保持原网格/PTY 尺寸、仅缩小下方可见区域并保留顶部锚点的方案，避免远端重复重排；不能仅保存本地 scrollTop 就宣称修复 tmux alternate screen。
3. 网格保持方案需验证键盘展开后底部光标可见性、触摸坐标和“回到底端”的映射；阅读锚点优先，主动回到底端时才允许改变可见区域。若必须调整 PTY，只在动画完成后合并一次 resize，并分别验证普通 scrollback、tmux copy-mode 和全屏 TUI 的锚点；若远端重排无法保证内容锚定，先解决该冲突，不把它当成已验收。
4. 旋转屏幕、修改字号及真实窗口大小变化仍正确 resize；这些操作与单纯 IME 切换分别处理。远端主动输出/清屏不等同于本机焦点引起的跳动，也不能靠冻结输出掩盖问题。

### 验收

- 普通 shell 历史、tmux copy-mode、合成全屏 TUI：暂停输出，停在中间某行，连续点击回复框/收起键盘 10 次；顶部文字锚点保持，无整页自动滚动、无从头回放、无额外按键发送。
- 对实际 Codex CLI / OpenCode / Kiro CLI 真机复测；键盘展开后功能键、回复框和底栏可达，终端仍能正确滑动和点击，回到底端能到达预期位置。
- 用文字锚点/截图和 resize 事件序列作证据，不只验证“终端仍有高度”；覆盖键盘动画、长草稿、横竖屏与新输出到达。
- 断线、pane 改变、未发送草稿、多行发送预览与重连仍有清楚提示；本轮不改变共享 tmux 尺寸和焦点的产品策略。

### 0.3.0 实现选择

采用“终端固定网格 + 顶部锚定 + IME 裁剪可见下部”，没有使用键盘动画后再 resize 的备选方案。顶部/输入栏固定，回复框固定高度以避免草稿增长驱动网格变化。只有显式点击回到底端才偏移可见范围以露出被键盘遮挡的底部，收起键盘恢复完整可视区域。旋转或字号修改仍真实 resize；主机持续输出不被冻结。原历史快照 UI 已移除，底部工具面板保留定向回复与手动重新绑定。

### 0.3.2 快捷键分页

快捷键栏仍占 40dp，不增加输入区高度或挤动终端。左右翻页不发送按键；点 F1–F12 发送标准 xterm 功能键序列，沿用 pane 目标校验，不提交手机草稿；断线或发送中禁用按键，仍可翻页查看。

## 6. 服务器文件夹、搜索与排序（0.4.0）

- 首页标题栏下增加搜索框、排序按钮和新建文件夹按钮。文件夹为单层本机分组，支持命名、重命名、展开/折叠与删除；服务器更多菜单提供“移动到文件夹”，含“未分组”。新增服务器默认未分组。
- 删除文件夹只清除分组关系，将其中服务器移回未分组；不删除服务器、凭据、缓存、最近记录或远端内容。删除服务器清理其分组关系，文件夹保留。
- 文件夹按创建顺序排列，未分组在最后；没有文件夹时保持原平铺列表。组内支持添加顺序、名称、最近使用三种排序，选择跨重启保留。名称按设备地区比较，最近使用取成功进入 shell/tmux 的时间，编辑/发现不算使用；同值保留添加顺序。
- 搜索忽略大小写并去除首尾空白，覆盖服务器别名、地址、用户名、文件夹名和本地缓存的 tmux 会话/窗口名。不搜索凭据或终端正文，不额外连接服务器。
- 搜索临时展开匹配的文件夹和服务器；命中服务器或文件夹时显示其任务，只有任务命中时仅显示匹配任务。清除搜索恢复原折叠状态。空结果给出提示，空文件夹可创建、重命名、删除。
- 文件夹名不能为空或重复（忽略大小写），限制 60 字符。分组和排序独立于 SSH 配置，移动/重命名不使凭据、信任、跳板路由、缓存及 30 分钟探测记录失效。
- 本轮不含嵌套文件夹、拖拽排序或远程文件管理。验收覆盖旧配置无迁移、跨重启持久化、隐藏地址搜索、缓存任务搜索、空结果、删除分组后数据保留以及原连接回归。

## 7. 首页刷新与文件夹状态（0.4.1）

- 自动刷新仅由冷启动、从后台回到首页触发；从 SSH/tmux、编辑或设置返回不触发。在终端或设置页回前台也不会留待返回首页补刷。
- 每台服务器间隔 30 分钟，失败尝试同样计时并跨重启保存；未分组可自动刷新。
- 文件夹展开/折叠状态持久化，折叠组跳过自动刷新。搜索临时展示子项不改变保存状态，也不解除自动刷新限制。展开本身不触发连接。
- 文件夹右侧增加圆形刷新按钮，一次刷新组内全部服务器，忽略搜索过滤、折叠状态和时间间隔。未分组同样提供组刷新。空组禁用，刷新期间显示进度；沿用最多两条探测连接并发和逐台错误/指纹处理。
- 不增加定时器；停留首页超过 30 分钟也不会自行发起请求。进入后台取消未完成探测。

## 8. 手机复制与连接提示（0.5.0）

- 终端“工具 → 选择复制”打开独立文字页；保留终端阅读位置与连接。文字为打开时的静态副本，新输出不改变选区；支持 Android 原生长按、选区手柄、复制菜单以及复制全部。
- 只取当前活动缓冲区已加载的文本，自动换行拼回原行，保留真正换行、中文和 Emoji；最多保留最近 20 万字符并提示截断。tmux 更早历史需先回终端滚动，再重新打开复制页。
- 复制页不发送远端鼠标或按键，文字仅保存在内存，关闭页面即可返回终端；剪贴板仅在用户复制时写入。
- 首页探测行与终端连接提示展示“跳板 N / 目标服务器 → 准备认证 → 连接并验证身份 → 读取/核对 tmux”；网络与认证由 SSH 握手共同处理，不伪装成精确百分比。
- 错误提供对应检查方向：域名/DNS、端口/SSH 服务、超时/网络、用户名/认证、密钥/口令、转发权限、tmux 路径或目标变化；不显示原始库异常及敏感内容。
- 下一轮设计优先级：Agent 状态卡、快捷回复、语音入口；具体安全投递和降级约束见主计划。

## 9. Agent 状态卡、快捷回复与主题（0.6.0）

终端标题下增加一行 40dp 的紧凑卡片，左侧 Agent 状态可点开查看文字依据，右侧快捷回复。关闭 Agent 状态提示后隐藏该行，工具中仍可打开快捷回复。卡片高度固定，状态变化不挤压终端；键盘继续只裁剪可见区域。

状态仅根据当前画面最后若干行的明确文字推测，可能等待确认、发现错误提示或未知；连接断开单独显示未连接。查看本机历史时不使用历史提示作为当前状态。无法保证识别所有远端 tmux copy-mode 或 TUI 格式，因此始终标明推测并提供依据，不推断完成/运行/卡死。

快捷回复以底部面板展示，点击填草稿，不发送。已有草稿弹出追加、替换或取消选择；每条可编辑或删除，也可新增。本地最多 12 条、每条 1000 字，控制字符受限制，发送前仍走现有预览及 pane 校验。

设置中增加跟随系统、浅色、深色选项，默认沿用深色；另提供 Agent 状态提示开关。浅色使用浅灰绿背景、深色正文、深绿操作与图标、深红错误文字；输入框、菜单、弹窗与选区需配套对比色。终端单独设置浅色 ANSI 调色板、光标、选区和 4.5 最低文字对比度，远端自定义真彩色由 xterm 尽量处理，不承诺所有 TUI 主题都无须自身配置。系统明暗变化不重建 Activity/SSH。

## 10. 首页状态灯与底栏快捷回复（0.6.1，覆盖第 9 节的卡片布局）

- 首页 tmux 名称前仅显示 8dp 圆点，和名称间隔 8dp；红：可能需要回答/处理，黄：正在运行，绿：正常完成，灰：未知/过期/刷新失败。颜色同时适配深浅主题，通过无障碍描述提供含义；设置中保留简短图例。
- 多 pane 窗口聚合红优先、黄其次，全部明确完成才绿，展开后各 pane 自己显示状态点。
- 状态是与列表一起刷新得到的缓存，并非实时监控。保持已有网络刷新规则；每分钟仅检查本机颜色是否已过 30 分钟，不新增服务器请求。
- 终端移除卡片、依据弹窗和轮询，恢复原终端空间。底栏按“工具 / 收起键盘 / 快捷回复 / 发送回车”排列，按比例分配宽度，标签保持单行。
- 快捷回复的编辑、持久化、草稿冲突选择、断线拦截及最终发送路径保持原规则。


## 11. 状态灯修复（0.6.2）

布局保持名称前圆点。读取标题状态和 CLI 当前输入区提示，绿灯含义补充为“本轮结束或已就绪”，灰灯继续表示缺少证据。每批采集结果抵达就显示对应颜色，不等待其他批次或本地下一分钟时钟。过期检查仍每分钟仅在本机执行，网络刷新规则不变。借鉴和验证记录见 [ui-062.md](ui-062.md)。


## 12. 认证与日志（0.6.4）

私钥模式下使用浅色/深色配套的圆角容器，首行显示就绪状态，下一行等宽文件/粘贴按钮；私钥口令继续独立放在下方。粘贴弹窗为 4–6 行输入区，默认遮蔽，可显示、主动读取剪切板、取消或导入。各级跳板复用此布局。

设置删除首页状态灯说明，在终端操作之后增加“调试日志”：一段简短容量/内容说明，加“生成日志”和“清空日志”。生成后使用系统文件保存界面，成功/失败返回原页文字提示。详细行为和边界写入 README 使用说明。

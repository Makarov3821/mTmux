# 终端分页指示点与首页下拉刷新计划

2026-11-01。基于 `2536851` / 0.9.3-rc.3，分页方向与首页下拉刷新已加入未发布工作区；实际行为与验证见[实现记录](../testing/terminal-file-preview.md)。以下保留交互约定与后续验收清单。

## 1. 四个分页指示点方向修复

用户要求：手指向左滑，当前快捷键页切换，亮点向右侧下一个点移动；向右滑则向左侧前一个点移动。指示器表达页面在四页序列中的位置，不跟随手指位移。

当前 `TerminalKeys.kt` 使用 `HorizontalPager(reverseLayout=true)` 和大虚拟页数循环，指示点按 `terminalKeyPage(currentPage) + currentPageOffsetFraction` 的原始索引向右绘制，未统一反向布局的视觉坐标。既有测试主要验证按键页内容/循环，不能证明亮点方向正确；这次不能只调整动画符号而忽略最终选中点。

计划：

- 明确“真实快捷键分组 → 视觉页序 → 点位置”的统一映射，使用同一映射更新连续拖动位置、最终选中点、页号与无障碍描述。保留现有四组按键、粘滞组合键、循环翻页和按键发送逻辑，不为了改亮点把整套快捷键内容反向两次。
- 单次完整左滑对应指示器 `1 → 2 → 3 → 4 → 1`；右滑反向。连续拖动时平滑跟随，取消/未过切页阈值时回到原点。
- 第四页到第一页、第一页到第四页从边缘连续衔接，不穿过中间三点倒放。亮点保持一个点大小，不恢复曾覆盖两个圆点的宽条。
- 保留当前分页操作时显现、停止滑动 5 秒后淡出的行为，透明快捷键与锁定修饰键样式保持一致。隐藏只改变绘制透明度，不占用额外高度、不触发终端 resize。

验收：

- 从任意一页左右滑动，核对实际按键内容、点最终位置、页号和拖动中的运动方向，而不只检查 `currentPage` 数值。
- 各方向至少循环两轮，覆盖首尾边界、半程松手回弹、快速连续反向、大虚拟索引和不同密度；任何时刻不出现两个实心亮点。
- 以可控 Compose 时钟检查淡出与再次出现；检查 Ctrl/Shift/Alt 等待字符释放、F1–F12 和普通键输入不受影响。standard/voice 共用组件，至少两种底栏均检查布局。

## 2. 首页顶部下拉刷新

### 触发和刷新范围

- 仅在服务器首页启用。列表还能向上回滚时，向下拖动先正常回到顶部；到达顶部后继续向下拉，才显示刷新提示。达到阈值后松手触发一次，未达到就收回；快速 fling、程序滚动、横向手势不能触发刷新。
- 首页品牌顶栏、搜索/状态总览保持固定；刷新指示器出现在固定区域下方、服务器列表顶部中央，不遮住系统状态栏或按钮，不把整个首页推出屏幕。空列表/内容不足一屏仍能感知下拉，零服务器时不发网络请求，保持可添加服务器的空态。
- 设置、服务器编辑、Doctor、指纹/更多面板、终端和文件预览中不启用首页刷新手势。搜索输入框选字/拖动不能被当成下拉；搜索词、排序、最近任务、分组/卡片展开状态及当前位置不因刷新重置。
- 本次是用户主动强制刷新，绕过 5 分钟自动刷新间隔，但仍遵守此前确定的折叠分组限制：只刷新已展开文件夹中的服务器和未分组服务器，不读取折叠文件夹。服务器卡片自身折叠不等于文件夹折叠，已展开分组中的折叠卡片仍可更新状态。
- 搜索临时展示的折叠文件夹内容不改变其保存的折叠策略；搜索词也不扩大刷新范围。默认按上述可刷新分组批量更新，不仅更新当前屏幕内的几个卡片；界面可说明“刷新已展开分组”。保留服务器/文件夹各自的手动刷新入口。

### 与当前刷新任务整合

当前首页以 `Column.verticalScroll(rememberScrollState())` 实现列表，`refreshVisibleFolders()` 会调用自动策略并检查间隔；单服 `refresh(profile)` 的手动路径则不检查折叠文件夹。新增批量入口应明确计算符合范围的目标，再强制间隔刷新，不能直接对所有 profile 循环手动刷新而绕过分组限制，也不能原样调用普通自动刷新导致 5 分钟内下拉没有网络更新。

- 持有可观察的列表 ScrollState，通过 nested scroll / 现有 Material3 的 `PullToRefreshBox` 接入，首次实施核对当前依赖版本 API。不新增第三方下拉库，也不改为捕获全屏触摸、阻断现有卡片按钮。
- 复用现有 `refresh` 管线、连接复用、每服务器去重、修订校验和 `Semaphore(2)`，不建立另一套 SSH 实现、不扩大并发、不新增后台保活。
- 每次建立批次 ID 与目标集合；已在刷新的服务器并入本次等待，不重复连接。所有本批目标已成功、失败、跳过或取消后结束全局指示器，不把 `rows.any(refreshing)` 当成本批永远不结束的条件。
- 沿用现有 Doctor/主机信任互斥策略；不因批量刷新自动弹一串指纹确认、不绕过信任校验。明确跳过的目标、旧缓存与错误继续显示在服务器卡片中。
- 刷新中再次下拉不叠加批次；成功的卡片即时更新，部分失败保留可用缓存和原有错误提示。完成时可用简短信息说明结果，不能部分失败仍宣称“全部刷新成功”。无符合范围的目标时立即回收并说明，无需假加载。
- 离开首页/后台按现有生命周期取消或结束本批显示；回来不重放这次强制批量动作。终端返回仍只强制对应服务器，其余符合范围的服务器继续按原 5 分钟策略，不受下拉入口影响。

### 刷新图标与动画

沿用当前 `UiSymbol.REFRESH` 线性图标和主题色：约 40dp 的圆形 surface 底、约 20dp 的图标，轻阴影与现有圆角面板一致；不固定 Chrome 的配色，也不引入模糊/图片动画资产。具体尺寸以首页 360/412dp 和大字体实测微调。

| 状态 | 反馈 |
| --- | --- |
| 空闲 | 不显示、不运行动画 |
| 下拉未达阈值 | 圆形提示随拉动从上方出现，逐渐增加透明度/轻微缩放；刷新箭头随拉动进度旋转，未触发网络请求 |
| 达阈值待松手 | 箭头完整显现并用 primary 强调，出现明确的“松开刷新”无障碍状态；初始阈值以约 64–80dp 试调，位移有阻尼与上限 |
| 松手刷新中 | 指示器回到稳定位置，箭头平滑切换为同尺寸旋转进度；不持续拉伸整个列表，卡片保留原刷新进度 |
| 未达阈值松手/取消 | 约 150–200ms 收回淡出，不刷新、不残留转圈 |
| 批次结束 | 约 150–200ms 回收淡出，失败由卡片/简短结果说明承担；不人为延长网络操作来凑动画 |

只在拖动/刷新期间运行动画，遵循系统关闭/缩减动画设置。无障碍提供“下拉刷新 / 松开刷新 / 正在刷新”与完成结果，避免每帧读屏播报；保留已有可点击刷新按钮供无法完成手势的用户使用。

### 验收

- 长列表中段向下拖动只滚动，到顶后继续拉并松手才触发；短列表、全部分组折叠、无服务器、搜索无结果均有正确行为。
- 检查未达阈值、到阈值后回拖、松手、手势取消、刷新中重复下拉及快速反向。图标各状态连续、关闭系统动画仍可操作，刷新结束后无无限转圈。
- 真实 SSH fixture 检查 5 分钟内主动下拉确实发起状态读取，折叠文件夹请求数为 0、并发最多 2、已有刷新不重复登录、部分失败不阻塞其他结果；只用假时钟/静态截图不能替代。
- 网络超时、切后台、切服务器、配置/指纹修订和从终端返回与刷新交错时，旧结果不能覆盖新配置；搜索/排序/展开偏好不被更改。
- 在当前主题、浅色和大字体下检查顶部间距、圆形底色与箭头对比度；逐帧检查下拉、松手和回收，而不仅截刷新中的一张图。持续动画测试使用可控时钟/有界条件，避免把 Compose 一直不空闲误判为网络失败。

实现顺序：先修正指示器方向映射并定向验证，再实现首页批次状态与触发，最后接入自定义图标/动画和 Android 手势/网络验收。文件预览继续按其独立计划推进，不将首页下拉手势接到终端或预览 WebView。

依据：[Android Compose 下拉刷新官方说明](https://developer.android.com/develop/ui/compose/components/pull-to-refresh)、当前 TerminalKeys / ServerHome / UiComponents 源码，以及现有刷新策略与用户明确的折叠分组约束。

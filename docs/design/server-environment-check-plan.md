# tmux Doctor：可选诊断、最小初始化与主页能力限制

状态：首版已实现，使用入口、交付范围和验证见 [tmux Doctor 说明](../testing/tmux-doctor.md)。下文保留后续扩展规划；基于业务提交 `c6a672b` 与现有 SSH 复用机制。

已确认决策：**tmux 3.2a 为最低兼容 baseline**。Doctor 对低于该版本在“版本”一行显示 ⚠️ 兼容性警告；不实现低版本元数据协议降级。旧版不是未安装，实际能力另行检查。仅 `mouse on` 的隔离探测在 3.0a、3.2a、3.4 均通过默认滚轮路径；3.0a 缺少当前应用所需的长度格式。发行版包映射、实测边界和证据见 [兼容性调研](tmux-compatibility-research-20261029.md)。既有端到端验证覆盖 3.4；将 3.2a 固定为产品 baseline 不代表已完成所有更高版本的手机回归。

## 目标和现状

在必须经过的 SSH 身份验证后，提供可选 tmux Doctor。Doctor 逐项说明使用适配情况；满足明确条件时，允许用户一键初始化当前远端登录用户的最小配置。主页新建 tmux 功能依据实际可用性开放，服务器三个点菜单始终提供重复运行 Doctor 的入口。

SSH 验证、Doctor 检查、应用配置是三个明确阶段：诊断本身只读，修改配置必须由用户在报告中主动点击；tmux 不可用不影响已验证服务器的保存及普通 SSH 使用。

当前 `ServerVerification.kt` 在 SSH 认证成功后直接保存服务器和已确认指纹，再按保留策略处理连接。`TmuxPreparation.kt` 在进入具体会话时校验目标；服务器启用了自动鼠标选项时，对该会话执行 `mouse on`。目前没有添加阶段的环境报告。

## 推荐交互

填写并点击保存 → SSH 主机身份检查、必要的指纹确认和认证 → 保存已验证的服务器 → 询问是否运行 Doctor → 诊断结果 / 可选配置 → 返回主页。

首次或未信任的指纹弹出确认；已有指纹仍会校验，但一致时无需用户重复批准。指纹变化继续按现有规则拦截。只有认证与本地保存成功，才显示 Doctor 邀请，不能在指纹弹窗刚关闭、认证尚未完成时就开始诊断。

邀请弹窗：

> 服务器已保存，要检查 tmux 使用环境吗？
>
> 检查安装、版本、滚动和历史记录等设置。检查本身不会修改服务器。
>
> [暂时跳过]　[运行 Doctor]

跳过后立即回主页，能力状态记为“未检查”。新增服务器只邀请一次；以后从服务器菜单手动运行。修改地址、登录用户、跳板或 tmux 路径会使旧报告失效，但不在每次连接时反复弹出邀请。

- SSH 失败：沿用重试、取消、Save anyway；强制保存仍表示未验证，不保存本次临时指纹。
- SSH 成功但 tmux 缺失、诊断超时或取消：服务器已经正常保存，保留已确认指纹；不回退保存，也不降格成未验证的 Save anyway。
- 原有 Save anyway 保留为 SSH 验证失败时的例外；此时仍标注未验证，不自动运行 Doctor。后续手动运行时须先完成正常的主机身份检查与认证。
- 报告不复用首页任务红黄绿灯的含义；首页以轻量“环境待处理”摘要为入口。

## Doctor 弹窗与逐项反馈

使用一个可滚动的诊断弹窗。各行从“等待 / 检查中”逐步变成结果，已完成项立即显示，失败不抹去其他项；依赖缺失的项目标为未检查。

```text
tmux Doctor                         开发服务器

✅ SSH 身份与认证             已验证
✅ tmux 可执行文件            /usr/bin/tmux
✅ 版本与基础命令             tmux 3.4
✅ 会话访问                   尚无会话，可以新建
⚠️ 用户配置                   未发现，可初始化
—  鼠标与历史实际值           尚无 tmux server，待验证
✅ 状态嗅探辅助命令           可用

[查看 / 生成最小配置]  [重新检查]  [完成]
```

以上为界面文案例子，不代表静态检查可以实测所有行为。结果图标配文字，状态为：✅ 通过、❎ 不可用/失败、⚠️ 可用但建议调整、— 未检查；运行时使用进度指示。不要把“没有 server”“尚未创建会话”“自定义绑定尚未验证”都画成 ❎。

版本行示例：`⚠️ tmux 3.1c：低于最低兼容版本 3.2a，部分功能可能不兼容，建议升级。` 3.2 也低于 3.2a，使用同一提醒；3.2a 及以上仅表示达到版本 baseline。版本提醒本身不抹掉其他检查结果，不等同于未安装，也不单独触发新建入口硬性禁用。

展开某行可查看当前值、作用范围、影响、建议和时间。tmux 未找到时展示“修改 tmux 路径 / 查看安装说明 / 重新检查”；普通建议不会禁止完成。底部配置操作按报告条件显示，不用每项再弹一个确认窗。

## 检查项目

| 检查项 | 收集方式与展示 | 判断边界 |
| --- | --- | --- |
| tmux 路径与可执行性 | 检查用户指定路径、PATH 解析结果及少量标准候选路径；运行 `tmux -V` | PATH 未找到不能直接断言没有安装；区分路径错误、无执行权限和执行失败；主页限制依据“当前 app 配置下不可用” |
| 客户端 / 服务端版本 | 显示命令行版本；已有 tmux server 时另读其版本；以 3.2a 为 baseline | 低于 3.2a 在本行显示 ⚠️“低于最低兼容版本 3.2a，部分功能可能不兼容，建议升级”；未知版本显示无法确认；核心能力另行检查 |
| server、socket 与会话 | 复用轻量目录发现，识别正常无会话、socket 权限错误、会话存在 | 没有 server 是正常状态；不为体检创建会话或启动 server；只检查 app 实际使用的 socket，不扫描所有用户进程 |
| 应用依赖能力 | 验证当前任务目录需要的格式字段；检查 `base64`、`head`、`tail`、`tr` 等辅助命令 | 命令存在与参数行为兼容分开判断；没有 server 时相关能力只能待验证；不读取 pane 正文或完整历史 |
| 鼠标与滚轮 | 读取全局默认和已有会话的有效 `mouse`；检查 root、copy-mode、copy-mode-vi 的上下滚轮绑定 | 默认绑定、缺失绑定、自定义绑定分别展示；复杂自定义逻辑仅提示人工确认；结合 app 的自动开启鼠标选项说明实际连接时行为 |
| 历史缓冲 | 读取全局/会话 `history-limit`，已有 pane 的实际 `history_limit` / `history_size` | 不能只看全局配置；0 或明显偏小才提示，阈值属于产品建议；不强推 500000 行 |
| 会话断开后的保留 | 检查 `destroy-unattached`、`exit-unattached` 等有效值 | 若设置会导致最后一个客户端离开后会话/server 退出，解释其与远程任务续接的关系，不擅自关闭 |
| 回复目标条件 | 检查 pane 的 `synchronize-panes` 等输入相关状态 | 提示同步输入可能影响多个 pane；保留现有发送前的实时身份和状态校验，报告不能替代它 |
| 基础显示环境 | 读取 UTF-8 locale；可用时检查 app 使用的 `xterm-256color` terminfo；查看 tmux 内部终端设置 | SSH exec 的 TERM 不等于交互 PTY 的 TERM；不据此宣称颜色/中文宽度已实测；缺少辅助工具显示未检查 |
| 用户配置与初始化条件 | 检查当前远端 `$HOME`、默认/XDG 配置位置、已知加载配置和写入条件 | 没有配置文件不等于从未用过 tmux；符号链接、非普通文件、已有配置、运行中 server 均不走新手初始化捷径 |

重点处理三个容易误判的地方：

1. **滚动不是一个开关。** 普通 shell 的历史滚动、tmux copy mode 和 Agent/TUI 自己接收鼠标事件是不同路径。静态检查只能确认配置与识别明显问题，不能承诺每个 Agent 的手势行为。App 的 1×～10× 仍是本地事件倍率，不和服务器滚轮步长同时自动放大。
2. **配置可能分层覆盖。** 报告应区分全局默认、会话/窗口/pane 的有效值和实际缓冲容量。只读取 `.tmux.conf` 文本不能替代运行时检查；无 server 时不能将文件中的一行配置判为已生效。用户配置可能含 include、条件和插件命令，不在后台执行配置文件来“验证”。
3. **修改 history-limit 不等于扩大旧缓冲。** 在用户此前使用的 tmux 3.4 中，此值的修改只作用于新建窗口，既有历史保留创建时的上限。不能承诺“修复后原 pane 立刻增加历史”，更不能为此重建用户窗口。[tmux 3.4 官方手册](https://raw.githubusercontent.com/tmux/tmux/3.4/tmux.1)

用户当前滚轮绑定的诊断规则：

- 当前 `WheelUpPane` 条件转发 / `copy-mode -e` 与 tmux 3.4 默认绑定相同，不能要求用户必须在文件中再写一遍才算通过。
- 当前 root `WheelDownPane` 按模式/应用鼠标状态转发事件；copy-mode 和 copy-mode-vi 的四个绑定把历史模式滚轮步长改为 8。tmux 3.4 的两个 copy-mode 表默认已有上下滚动绑定，默认步长为 5。[tmux 3.4 默认绑定源码](https://raw.githubusercontent.com/tmux/tmux/3.4/key-bindings.c)
- 诊断以运行时绑定和受测版本默认机制为准，不能因为 root 表没有显式 `WheelDownPane`，或配置文件里没有这些行，就断言不能滚动。
- `-N 8` 只针对指定 copy-mode 动作；Agent 接管鼠标时，转发的滚轮由 Agent 处理，不保证每个事件也是 8 行。与 app 的事件倍率叠加时可能滚动过快。
- 对用户这一类已知绑定显示“已配置历史滚动，步长 8”；不改回默认，不将步长不同作为不兼容或禁止新建的依据。复杂自定义逻辑仍显示待实测。
- 新手最小模板依赖受测 tmux 的默认滚轮绑定，不额外复制这组加速绑定；若有效默认绑定确被删除，提供具体修复建议。

移动端自由滚动的兼容目标：

- copy-mode 同时承担 tmux 的历史浏览，不是仅用于复制文字。用户不必手动进入，但普通 shell 的滚轮路径仍需要正常进入、上下滚动及回到底部退出；可以不定制步长，不能忽略历史模式的有效绑定。
- 稳定滚动需要联合检查：app 的远端触摸转发已开启且收到鼠标协议启用信号；tmux 的有效鼠标配置；上滚在普通 shell 进入历史、在应用接管鼠标时转发；历史模式上下滚动及自动退出；实际 pane 存有历史。仅提高 `history-limit` 或补 root 两个绑定不足以覆盖整条路径。
- 对 Agent/TUI，鼠标事件应继续转发给应用，由应用决定内部内容如何滚动。某个程序没有相应鼠标/历史功能时，tmux 配置不能替它实现“所有内容都可上下浏览”，也不自动用方向键代替滚轮。
- 某些旧版本或被配置/插件改坏的环境需要补充显式滚轮绑定；Doctor 不能只检查 `mouse on`，也不能盲目恢复当前版本的一整套绑定。
- 至少按历史断点区分兼容策略：2.0 及以前使用旧鼠标配置；2.1 起统一为 `mouse`；2.4 起使用新的 copy-mode / copy-mode-vi 和 `send-keys -X/-N`。用户当前的多行花括号绑定也不能直接假设老版本接受。参考 [2.1 变更](https://raw.githubusercontent.com/tmux/tmux/2.1/CHANGES)、[2.4 变更](https://raw.githubusercontent.com/tmux/tmux/2.4/CHANGES)。
- 现有端到端实测覆盖 3.4，已确定产品最低 baseline 为 3.2a；受支持版本分别验证读取能力、配置语法、鼠标协议和手势行为后，再增加对应修复模板。低于 baseline 只提示兼容性，不增加旧版协议降级路线。能滚动不等于当前 app 的元数据发现、创建和输入保护在该版本都兼容。
- 普通 shell、历史模式、鼠标接管的 TUI 应分开给结论。静态配置检查与手机实测分别记录；未实测的旧版本不显示“全部适配通过”，也不承诺一份配置适用于所有版本及所有程序。

## 新手最小配置：首版包含

“从未用过 tmux”不能可靠地由机器自动判断。满足以下条件时推荐初始化：tmux 已安装且模板选项兼容；检查范围内没有运行中的 tmux server；默认及 XDG 用户配置位置没有现有配置或符号链接；当前登录用户的 HOME 可确认且可写；用户确认这是首次配置、没有其他自定义配置/socket，并点击“生成最小配置”。有配置检查权限不足时不推断为“没有配置”，只检查默认 socket 也不能声称已排除所有自定义 server。

预览明确显示目标为**当前 SSH 登录用户**的 `~/.tmux.conf`，不是其他用户名下或系统级配置。已有系统配置只作影响提示，不修改系统文件。存在未知自定义加载方式时转到建议模式。

初始模板建议如下，历史容量 10000 行作为新手默认，可在预览中调整：

```tmux
# mTmux minimal config v1
set -g mouse on
set -g history-limit 10000
set -g destroy-unattached off
set -s exit-unattached off
```

模板围绕触摸滚动、历史和断开后的会话保留；不引入插件、额外滚轮倍增、shell 命令或启动钩子。选项由实际兼容性决定，不给未知旧版本硬写模板；已有用户的历史容量不统一改成 10000。相关选项语义参考 [tmux 官方手册](https://man.openbsd.org/tmux.1)。

应用操作为“预览内容与位置 → 创建最小配置 → 复查文件”。以当前登录用户权限排他新建：若写入时文件已出现、变为链接、权限变化，立即停止，不覆盖；写入失败不得损坏已有文件。记录创建结果和内容摘要，供“撤销本次初始化”使用；只有仍是 app 创建且内容未被外部修改的文件才能直接撤销。

文件写入成功与运行时生效分别显示。无 server 时提示“配置已创建，将在下次启动 tmux 时加载”，鼠标/实际历史等项目仍可保持待验证。Doctor 不为刷绿而后台新建会话。用户随后通过主页创建第一个命名会话，创建后复查对应配置；如有其他方式先启动 server，应重新读取有效值，不依赖旧报告。[tmux 配置加载规则](https://man.openbsd.org/tmux.1#DESCRIPTION)

## 已有配置用户：逐项建议

已有配置或运行中 server 时，首版展示明确建议、可复制片段及作用范围，不整文件覆写或重新 source 用户配置。后续可增加逐项选中后应用的能力：

- 当前会话的鼠标设置与现有自动开启鼠标保持同一策略；自定义滚轮绑定不默认替换。
- 每项显示作用范围：pane、窗口、会话、用户配置或整个 tmux server；同一会话的其他客户端也可能受影响。
- 应用前保存局部覆盖/继承关系；撤销时恢复原关系，不把有效值硬写为新的覆盖。外部修改导致状态变化时先重查。
- 扩展持久配置需有独立受管理片段、备份、幂等更新与撤销；首版新手创建不依赖整文件编辑。
- 未安装 tmux 时提供安装说明，不自动 sudo、安装软件、升级已有 server 或关闭任务。

## 主页新建 tmux 的能力限制

建议保留可发现的入口：确认不可用时将加号置灰，卡片注明“tmux 不可用”，三个点中的 Doctor 和编辑路径仍可用，而不是无解释地隐藏功能。

| 能力状态 | 主页行为 |
| --- | --- |
| 未检查 / 跳过 Doctor | 保留新建入口；点击先做轻量可用性检查，失败说明原因并拒绝创建，成功后打开命名窗口 |
| 可用但暂无会话 | 正常允许新建；没有会话不是禁用条件 |
| 可用，只有鼠标/历史等建议 | 正常允许新建，建议不会成为硬性门槛 |
| 最近确认路径不可用 / 无执行权限 / 核心能力不支持 | 新建按钮置灰并说明原因；菜单提供重查、编辑路径和安装说明 |
| socket 权限、网络中断或本次检查超时 | 显示具体故障或未能确认，不记为“tmux 未安装”；暂时不能创建时允许重试 |
| 报告过期或连接配置已修改 | 回到待验证状态，允许点击后重新轻量检查，避免装好 tmux 后被旧报告永久锁住 |
| 主机身份未验证 / 已变化 | 先走正常主机验证；Doctor 或新建入口不能绕过信任检查 |

前端置灰只是交互提示。真正执行新建时，仍在同一 SSH 链上验证可执行性和会话名冲突；不能只依赖缓存。发现环境变化就更新能力状态。部分嗅探辅助命令缺失只影响相关功能，不直接等同于不能创建会话。

硬性不可用结果建议以 5 分钟作为初始有效期；过期不额外后台轮询，用户操作时重查。手动 Doctor、编辑路径或实际新建成功可立即更新状态。tmux 不可用时普通 SSH 入口始终保留；已有任务缓存不能继续暗示 tmux 可用，点击恢复仍需验证实际目标。

限制状态的产生、解除和清理按以下事件执行：

| 事件 | 状态变化与入口行为 |
| --- | --- |
| Doctor、点击新建的轻量检查、或执行新建前的检查明确确认当前 tmux 路径不可执行/创建必需能力不支持 | 对当前连接配置产生一条带原因、检查时间、有效期的不可用记录；立即限制新建 |
| Doctor 或其他实时验证确认满足创建需求 | 立即清除相同配置下的不可用记录，恢复入口；不要求鼠标、历史等建议全部变绿。当前同服务器操作尚在执行时，另用临时 busy 状态防止重复提交 |
| 从失败检查结束起满 5 分钟 | 不可用记录过期，回到“待检查”，入口允许点击后先验证；不是自动宣称 tmux 已恢复。前台到期或返回页面时本地更新显示，不需要后台 SSH 轮询 |
| 修改主机、端口、用户、跳板、凭据、信任身份或 tmux 路径 | 旧修订报告和限制失效，回到“待检查”；新的信任问题仍先走主机验证 |
| 网络超时、断线、用户取消、会话名重复、普通配置建议未通过 | 不据此生成“tmux 未安装”的限制；分别显示重试、校验或建议。未知的创建失败不自动归因于 tmux 缺失 |
| 安装好 tmux、修好 PATH/权限或创建配置文件 | app 无法仅靠服务器外部改动立即得知。用户主动重查可马上恢复；否则过期后下次点击验证。仅写入配置文件不等于安装 tmux，不单独恢复可用状态 |
| SSH 连接回池/关闭、退出终端、最后一个会话结束、tmux server 正常退出 | 不因此改变可执行文件的可用性，也不新增创建限制；暂无 server/会话仍可新建 |
| 删除服务器 | 清除它的 Doctor 报告和能力状态；其他服务器不受影响 |

旧请求结果须匹配当前配置修订，过期结果不能重新限制新配置。新建入口是否允许尝试和当前是否已有可用 SSH 连接是两回事；不要把连接池状态当成 tmux 可用性。

## 服务器三个点菜单

增加“tmux Doctor / 检查使用环境”，无论上次成功、失败、跳过或 tmux 未安装均可打开。每次打开启动一轮检查；若已有报告，读取期间先展示带时间戳的历史结果，明确区分新旧。弹窗内“重新检查”可再运行一轮。

重查成功立即刷新配置建议和新建能力；重复运行不自动重写配置，Doctor 写过的配置文件识别为已存在。保留原有“验证主机指纹”，两者共用 SSH 信任机制但用途分别清晰。

## 性能与连接生命周期

- 邀请及时点击且链仍有效时，复用刚完成指纹验证和认证的同一条 SSH 链。通常使用一个批量 exec 完成基础检查；确有必要时再追加一次。该路径新增 SSH 握手次数目标为 0，exec channel 仍有自身的网络往返。用户选择不保留连接、邀请停留过久或回到菜单后运行，允许正常重新连接，不为了可选诊断违背保留档位。
- 基础检查以 3～5 秒额外预算为初始目标，允许取消/跳过，不能保证任意网络下达到固定耗时。当前 exec 的通道建立与命令等待各有超时，应为体检明确一个整体 deadline。
- 不调用完整任务屏幕探测、不下载历史、不扫描插件目录；会话/pane 元数据数量与总输出设上限，大服务器显示已检查数量，剩余项按需展开。
- 保存后的同服务器首页刷新与 Doctor 协调执行，避免争抢刚建立的连接并额外握手；已有轻量目录发现成功可更新可用性，但不冒充完整 Doctor 已通过。跳过 Doctor 后按正常首页刷新规则继续。
- 保存已完成后再展示邀请；连接先按原连接池档位处理。Doctor 运行时持有活动连接，完成或取消后归还/关闭，邀请与报告阅读不另设无限保活。“无保留”仍遵循零空闲保留；首次邀请运行 Doctor 可能因此需要重新连接。
- 报告本地缓存，按服务器连接配置、已信任主机密钥与 tmux 路径/路由区分；编辑这些字段时失效。首页 5 分钟刷新、返回时刷新对应服务器、折叠分组限制维持原有范围，环境体检不挂到每次任务刷新上。
- 菜单手动重查、路径/认证变更后重查；已有报告标明检查时间。进入具体会话时仍做原有轻量准备和必要的目标校验，不重复整个体检。
- 诊断结果和 `TmuxAvailability` 分开存储，后者包含原因和有效期。对同一服务器的重复 Doctor 合并或取消旧请求，以连接配置修订号防止旧结果覆盖新状态；新建和应用配置也需避免重复提交。
- 日志记录连接复用、路径定位、版本、目录读取、配置检查、配置创建/撤销结果、耗时与退出码，不记录密钥、口令、pane 正文和完整配置文件。

## 落地顺序与验收

首版按三个可验收步骤落地，最终一起交付：

1. 指纹验证及保存后的邀请、只读 Doctor、逐项结果弹窗和服务器菜单重查。
2. 能力缓存、主页新建入口限制和执行前再验证；保留普通 SSH。
3. 符合条件的新手最小配置预览、排他创建、复查与撤销，创建第一个会话后核实生效。

已有复杂配置的自动编辑、交互测试页、扩展键与剪贴板适配继续作为后续功能。

代码可拆为 `TmuxEnvironmentProbe`（命令与解析）、`EnvironmentCheckReport`（每项状态和范围）、`TmuxAvailability`（主页门控）、`TmuxDoctorDialog`、报告缓存及 `TmuxConfigBootstrap`（受限模板、排他创建、撤销）。添加验证流程发出保存成功后的可选邀请；复用 `SshClient`、轻量目录发现和有边界的输出协议，不复用重型 pane 屏幕扫描。

验收覆盖：邀请运行/跳过、指纹拒绝/变化、强制保存后手动 Doctor、tmux 未安装/不在 PATH/无执行权限、SSH 成功但 exec 受限、无 server、新手初始化、XDG 配置/符号链接/无写权限、创建竞争和写入失败、文件被外部修改后的撤销拒绝、重复诊断不重复写入、配置已写但尚未生效、已有会话且局部覆盖、默认/自定义/缺失滚轮绑定、新旧历史容量不同、版本后缀、未知字段与旧版本、辅助命令缺失、会话检查中消失、超时取消、报告过期、安装 tmux 后恢复新建、点击期间环境变化、长时间阅读报告、无保留档位、跳板和旧请求晚返回。

你此前的 tmux 3.4 可作为首批实机基线；新增受测版本后再声明兼容范围，不凭版本号直接保证所有功能正常。Doctor 检查阶段不会创建/关闭远端会话、不改变当前 pane、不修改配置；只有用户主动应用配置才进入写入阶段。tmux 问题不抹掉已完成的 SSH 信任验证与服务器保存。

选项作用域、鼠标、alternate screen 和终端语义参考 [tmux 官方手册](https://man.openbsd.org/tmux.1)。阈值、预算、分期和交互均为本项目的设计建议。

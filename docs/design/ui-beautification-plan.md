# mTmux 界面美化方案

基于用户提供的 [12 界面 HTML](../ui-template.html) 和当前 0.8.2 代码整理。本方案已实现并固定为 0.8.3（versionCode 31）。实现和验证记录见 [UI 改版报告](../testing/ui-refresh-report.md)。

0.8.4 的终端底栏调整：取消键帽底色、输入框描边、分隔线和收起键盘按钮，发送合入输入区；标准版工具、快捷回复均分底栏并各自居中，voice 版中央放置跟随主题的圆形声波按钮、两项操作在两侧空间内居中；新增一次性 Ctrl / Shift / Alt 组合与首尾循环翻页。当前改动及截图见 [终端组合键与循环翻页](../testing/terminal-keyboard.md)。下文保留 0.8.3 原方案。

最新底栏布局效果图：PNG（历史截图已清理） / [HTML 预览](mockups/terminal-dock-v3.html)。并排展示标准版、Tokyo Night 深色语音版与 Paper 浅色语音版，使用提供的声波图标及当前代码的配色、156 dp 底栏、52 dp 圆形按钮；这是浏览器绘制的布局示意，非 Android 实机截图。HTML 可点击 Ctrl / Shift / Alt 查看高亮。

## 设计方向

采用模板的圆角卡片、分层底色和胶囊操作区，保留单列服务器列表及终端优先的信息结构。首页突出“服务器 → 窗口 → pane”，终端突出“当前目标 → 输出 → 草稿 → 发送”，设置按用途组织。

首页使用一层服务器卡片和一层任务背景即可；文件夹使用轻量分组标题，避免每一级都增加边框、阴影和大间距。终端正文占主要面积，装饰集中在顶部栏和底部操作区。

## 1. 视觉规范

| 项目 | 建议 |
| --- | --- |
| 主方案 | Tokyo Night 深色、Paper 浅色；保留接近现有界面的 Emerald 选项 |
| 其他主题 | Catppuccin、Zinc、Nord 与主方案一起补齐浅/深配色，六套主题均支持跟随系统 |
| 背景层级 | 页面底色、服务器/设置卡片、任务/输入区三级；强调色只用于选中、主操作和焦点 |
| 圆角 | 主卡片 16–18 dp，任务/输入区 10–12 dp，抽屉顶部 24 dp |
| 间距 | 页面左右 16 dp，卡片内 12–16 dp，卡片间 12 dp，行内 8 dp |
| 字号 | 页面标题 20–22 sp，服务器/设置项 15–16 sp，任务 14 sp，辅助说明 12–13 sp |
| 图标 | 统一矢量线性图标，视觉尺寸 20–24 dp；图标操作保留至少 48 dp 的点击区域 |
| 字体 | 普通界面使用系统字体；命令、地址、指纹和终端使用等宽字体，字体随 APK/系统提供，无运行时下载 |
| 状态色 | 注意/运行/就绪/未知使用明确语义色，和主题强调色分开；配合无障碍描述及必要的文字说明 |

模板的六套色板目前是五套深色、一套浅色，不能直接作为“六套主题 × 三种明暗模式”的完整实现。实现时已为六套主题补齐浅深版本，并联动终端背景、文字、光标及选区；ANSI 使用按明暗区分的统一语义配色。

建立统一颜色、圆角、间距和文字样式，由 Compose 界面、WebView 背景、xterm 光标/选区/ANSI 调色板共同使用。切换颜色只更新绘制属性，不重新创建终端或触发远端尺寸变化。既有用户保留现有偏好，新配色由用户主动选择。

## 2. 首页：服务器卡片和任务层级

- 顶部保留“服务器”、设置和添加；搜索框降低轮廓强度，排序和新建文件夹使用统一的图标按钮。
- 文件夹标题展示名称、数量、刷新和更多；折叠、搜索与排序沿用当前行为。
- 每台服务器使用独立圆角卡片。第一行是名称、上次更新时间及 SSH / 刷新 / 更多，长名称在可用宽度内省略，操作按钮保持可点。
- 单 pane 窗口显示一行任务底色；多 pane 窗口展开后，以左侧细引导线与缩进区分子项。标题保留会话与窗口名，pane 编号作为辅助信息。
- “上次使用”改为低对比小标签，长任务名优先获得空间。任务多时保持紧凑，避免卡片嵌套造成过多滚动。
- 刷新进度放在服务器卡片内部；读取列表时保留尚未过期的旧颜色，按批替换。点击任务交接 SSH 时显示简短进度与取消，保留 0.8.2 的状态采样时间和连接归属规则。
- 普通连接失败使用卡片内提示条；首次指纹核对和密钥变化使用不同文案。任务状态点与连接异常提示分开，避免将“任务需要处理”和“SSH 断开”混为一谈。
- 空状态采用小终端图标、两行说明和一个添加按钮；standard 的说明不宣传自身不具备的语音功能。

## 3. 终端：胶囊顶栏和统一底部操作区

- 保留现有 48 dp 顶栏，中央胶囊显示服务器与任务，长名称省略并可点击查看详情；右侧保留回到底端。
- 底部沿用现有快捷键、草稿输入框、操作按钮三层结构：快捷键增加浅底键帽；输入框增加明确的焦点描边；“发送回车”使用唯一的实色主按钮，其余操作使用弱强调。
- 保留标准版与语音版现有按钮顺序。语音版麦克风获得独立的点击区域，不能靠缩小“工具、收起键盘、快捷回复、发送”的文字来塞入。
- 在现有尺寸预算内进行美化：顶栏 48 dp、底部 156 dp，总计 204 dp。保持 WebView 逻辑高度和键盘裁剪机制，键盘弹出、状态提示和抽屉出现时不改变远端行列。字体放大或屏幕空间不足时，需要明确的自适应布局和独立回归验证。
- 断线提示沿用覆盖层，增加圆角、异常图标、错误摘要和重连按钮；历史标识清晰，正文保持可读，草稿仍可编辑，发送保持禁用。取消模板将整个底部区统一降低透明度的做法。
- 连接状态、pane 与尺寸以实际数据为准；模板中的 `80×24`、`BOUND PANE` 等只作为设计示例。

## 4. 设置与服务器编辑

设置使用五组卡片：

1. **外观与语言**：明暗模式、主题色预览、语言选择。
2. **连接**：SSH 保留五档“无 / 少 / 中等 / 多 / 很多”，对应 0 / 1 / 2 / 3 / 5，默认两条；说明保留一分钟、退后台关闭。
3. **终端与输入**：字号、触控、远端滚动倍率（1×～10×）。
4. **隐私与语音**：隐私显示；voice 版额外展示离线语音设置。
5. **诊断**：生成/分享日志、清空及空间说明。

卡片内使用清晰的设置行，说明文字放在对应控件下方，避免每行都单独嵌套卡片。SSH 五档可使用横向分段选择，选中后在下面显示“最多两条 · 空闲一分钟”之类的说明。

服务器编辑沿用模板的“目标信息 / 认证 / 高级选项”三块。地址与端口同排，账号独立一行；认证方式切换后只展示相关字段。跳板链用简洁路由条展示，长链可换行，跳板条目支持折叠及原有排序、删除和从已保存服务器选择。

## 5. 新增：远端滚动倍率 1×～10×

这是用户在美化方案基础上追加的功能修改，随终端操作区一起实施。

- 将当前 0.5×～2× 的远端滚动速度调整为 **1×～10×**，提供 1、2、…、10 共十档，默认 1×。设置页和终端工具抽屉使用同一项偏好，调整即时生效并跨重启保存。
- 在 mTmux 客户端增加同样滑动距离生成的标准滚轮事件数量。继续使用现有 SSH 传输，不更改服务器的 tmux 配置，不增加连接、握手或后台轮询。
- 1× 表示现有 1× 的基准手势响应，10× 表示在限速范围内生成约十倍滚轮事件；最终行数由 tmux 或应用每个事件的响应决定，不标成“每次固定十行”。适用于 tmux 历史和接收鼠标事件的 Agent/TUI；不使用方向键代替鼠标滚轮。
- 结合滑动距离累计与按帧发送，实现可控的倍率。高倍率允许每帧发送有上限的多个事件，避免当前“一帧最多一个事件”的限制让不同档位过早表现相同；队列有界，松手、取消、断线或切换目标时清理未发送事件，避免松手后持续滚动或事件落到新目标。
- 设置页、工具抽屉、原生到 WebView 的桥接以及 JavaScript 的取值限制一并更新，不能只扩展滑块。旧偏好迁移为范围内的最近整数档，小于 1× 的值归为 1×，无效值使用默认值。
- 界面名称使用“远端滚动倍率”，显示当前的 `1×`～`10×`；说明用“同样距离滑动时，向远端发送更多滚轮事件”。普通 shell 的本地历史滚动保持现有路径。
- 验收覆盖 1×、中间档和 10× 的事件数量、上下方向及鼠标位置；分别确认 tmux 历史和支持鼠标的应用能加速。检查两处入口同步、重启持久化、旧值迁移，以及高倍率下的帧调度、队列边界和目标切换清理。

## 6. 抽屉和弹窗

- 工具抽屉统一标题、拖动条、目标卡和动作行。复制、粘贴、绑定等已有动作按用途分组；可容纳长文案的动作优先用整行，窄屏不强行放两列。
- 快捷回复使用易读的列表，填入草稿与编辑使用独立点击区域，已有草稿继续明确选择追加/替换。
- 语音面板区分“录音、转写、结果”状态，分别展示可用操作；结果按钮写“填入草稿”，不附带回车符。实现采用真实录音计时与 60 秒进度，不使用模拟波形或持续装饰动画。
- 静态复制页使用大面积可选择文本，清晰标示静态副本；保留原生选区手柄。
- 指纹确认、私钥导入和多行发送预览统一视觉样式，同时保留对应的身份核对、遮挡、禁止自动发送及敏感页面截屏策略。

## 7. 模板需要修正的地方

1. 大量 10–11 px 文案及 28–34 px 图标按钮适合作为总览示意；正式界面要按上面的字号及触摸区域放大，接受相应的内容高度增加。
2. 去掉全局发光、持续状态灯动画和背景模糊。使用底色、细边框及必要的轻微阴影表达层级，降低重绘和电量开销。
3. 系统状态栏交给 Android；模板中的 `WARM POOL · 2 ACTIVE`、`FLAG_SECURE ON` 和文件名不进入正式产品界面。任务和连接信息只展示对用户有用的部分。
4. 当前隐私功能并非“隐藏地址即全应用禁止截屏”：隐私显示开启时普通脱敏页面可截图，敏感页面始终保护。正式文案应沿用真实规则，修正模板中的合并描述。
5. 语音自动语言检测当前默认关闭，关闭时使用界面语言；模板里的 `Auto` 不作为默认值，也不新增尚未实现的模型/语言选择能力。
6. 模板中的多个弹窗上下并排仅是设计展示；运行时按实际操作依次出现，避免叠放两个模态确认框。
7. HTML 的展示标题与“保留 38 个测试”等示例不作为实现事实；保留实际已有的 testTag、语义描述和行为回归。

## 8. 实施顺序与验收

**第一批：主题规范、首页、设置和服务器编辑。** 先统一颜色与通用卡片/按钮组件，再落实首页层级与设置分组；可独立检查整体风格和信息密度。

**第二批：终端与底部操作区及滚动倍率。** 保持当前空间预算和逻辑网格，完善键帽、输入框、连接提示、standard/voice 按钮宽度及键盘状态，并实现第 5 节的客户端 1×～10× 远端滚动倍率。

**第三批：抽屉、弹窗和其他配色。** 统一复制、语音、快捷回复及确认弹窗，补齐其余主题的明暗配色与终端颜色。

每批用实际原生页面截图检查中英文、浅深色和 360/412 dp 宽度，并覆盖长服务器名、多 pane、空状态、刷新失败及大字体。终端单独检查键盘开关、历史阅读锚点、选区与滚轮、输入不重放、断线后发送禁用、主题切换不重建连接，以及语音/快捷回复只填草稿。

视觉动效只用于短暂的选中反馈、颜色和列表展开；终端逻辑尺寸不参与动效。实现继续使用 Compose 与已有终端资产，资源随 APK 打包，不增加远端状态轮询或界面运行时下载。

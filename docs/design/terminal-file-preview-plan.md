# mTmux 终端文件预览实施计划

2026-10-30 制定；2026-11-01 已实现基础版，仍未发布。实际行为、资源边界与验证见[实现记录](../testing/terminal-file-preview.md)。本计划承接[可行性调研](terminal-file-preview-research.md)，下列分阶段验收继续用于后续真机覆盖。

## 目标与首版范围

用户点击 Agent 或普通终端输出中的文件链接后，在应用内打开可关闭的预览面板，阅读远端 Markdown、静态 HTML 或图片。外部 HTTP(S) 链接交给手机系统浏览器。

文件路径按当前服务器解释，不要求服务器安装插件、启动 HTTP 服务，也不要求更换 Agent。复用已有认证 SSH 链，新增按需 SFTP 通道；不增加常驻 SSH 或后台轮询。

| 目标 | 首版行为 |
| --- | --- |
| Markdown：`.md`、`.markdown` | 标题、段落、列表、引用、表格、围栏代码、链接、图片；代码块保留空白并可横向滚动 |
| HTML：`.html`、`.htm` | 静态文字、布局、CSS、受控本地图片；页面 JavaScript 不执行 |
| 图片：PNG、JPEG、WebP | 适应窗口、双指缩放、拖动、双击放大/复位；显示实际采用的采样情况 |
| HTTP(S)，包括以图片/HTML 扩展名结尾的网址 | 系统浏览器打开，保持一致的外链规则 |
| 不支持的文件类型、目录 | 说明原因并允许复制路径；不执行文件、不启动远端程序 |

初版不包含 PDF、SVG、动图播放、视频、Mermaid、数学公式、完整语法高亮、网页脚本、CDN 自动加载、超大图原分辨率分块、文件编辑和 SSH 端口转发。它们不阻碍基础预览交付。

## 固定的交互

1. 终端短按命中可识别链接，优先处理链接；本次手势不再发送远端鼠标点击，也不唤起键盘。普通位置的短按、长按和滑动沿用现有终端逻辑。长按不承担新的链接菜单功能，避免抢占现有远端右键。
2. 文件点击后立即弹出应用内大面板，显示文件名、服务器、解析后的路径、加载进度、关闭按钮；窄屏接近全屏，宽屏限制阅读宽度，沿用主题和安全截图策略。无需系统悬浮窗权限。
3. 打开时隐藏 IME、暂停终端直接输入；终端输出继续接收和渲染。关闭后恢复终端可交互状态，默认不自动弹键盘，用户点终端再输入。
4. 预览中的同文档锚点就地滚动，关联文件在同一面板内导航，保留有限返回历史；图片可进入图片预览。顶部返回先退文档历史，无历史时关闭，关闭按钮始终退出整个预览。
5. 系统返回键优先关闭已有 IME，再执行预览返回。读取失败显示具体类别和重试入口，不显示原始异常堆栈或服务器凭据。
6. 关闭面板取消未完成下载、销毁预览 WebView、释放位图与临时文件。已经加载的内容可在网络断开后继续看，但不继续读取关联资源；切换服务器/任务、重连导致连接标识变化、退出终端时关闭预览。

流程：`终端链接 → 绑定连接与目标 → 解析路径 → 临时读取 → 预览 → 关闭清理`。HTTP(S) 在链接分类后直接进入系统浏览器，不走文件读取。

## 链接识别与手机触摸

识别优先级：明确的 OSC 8 URI，高可信可见 HTTP(S)，带路径结构及支持扩展名的文件路径。相同区域优先使用 OSC 8 的实际目标，不能用可见标题覆盖它。只有彩色标题且没有 URI/路径时无法推导真实目标，不伪造可点击行为。

- OSC 8：接入 xterm `linkHandler`，允许接收非 HTTP URI 后由原生白名单分类；不能直接 `window.open` 任意 scheme。
- 普通网址和文件：使用基于公开 buffer / link provider API 的受限识别器，统一提供范围与目标。优先共用该识别器处理网址，只有跨行网址质量不足时才引入与 xterm 5.5.0 兼容的 `addon-web-links`；不为此升级整个 xterm。
- 文件形式先支持 `/absolute/file.md`、`~/file.md`、`./doc/file.md`、`../doc/file.md`、`docs/file.md`，以及有明确边界的带空格路径。带引号或真实 URI 可以保留空格；裸露且无法确定边界的路径不猜测。
- 可识别 Markdown 语法仍留在终端文本中的明确路径目标，但终端显示结果不等同于 Agent 原始 Markdown AST。不能承诺从所有排版形式恢复隐藏地址。
- 支持常见 `file.md:123`、`file.md:123:4` 后缀，按结构提取行号，不能无条件删除文件名中的冒号。行号只作为可选位置提示，Markdown/HTML 渲染视图首版不保证精确定位源码行。
- `file:` URI 指向当前远端，不指向手机文件系统。authority 与当前远端身份不符或无法确定时提示，不静默换服务器。相对引用按路径处理；`javascript:`、`data:`、`content:`、`intent:` 及编辑器专属 scheme 不透传到系统。

现有 `terminal-touch-surface` 覆盖 xterm，`touchstart/end` 还会 `preventDefault` / `stopImmediatePropagation`；仅安装链接 addon 不会解决点击。实施时在短按释放后先完成命中判断，命中才消费，否则继续既有远端点击和 IME 流程。拖动超过既有阈值仍为滚动，不能在滑动末尾打开链接。

不依赖 `_core` 等私有字段。OSC 8 命中可先验证“向 screen 发仅供命中探测的 mousemove，经公开 hover 回调获取 URI/range”这条路径；探测不能产生远端鼠标流、焦点变化或粘滞鼠标状态。普通文本命中可直接使用相同 buffer 坐标计算。鼠标、触摸笔也要避免重复激活。

坐标使用 screen 实际 `getBoundingClientRect()`，考虑现有键盘避让 transform、字体、设备缩放、中文宽字符、emoji、换行与 viewportY。缓存随内容改写、滚屏、resize、字体和连接改变失效；只扫描候选逻辑行并限制长度，不每帧扫描完整 scrollback。候选必须在按下和释放时仍指向同一链接，输出变化不把一次短按迁移到另一个目标。

依据：[xterm 链接处理](https://xtermjs.org/docs/guides/link-handling/)、当前仓库 xterm 5.5.0 的 `typings/xterm.d.ts`、`src/browser/Linkifier.ts`、`src/browser/OscLinkProvider.ts`，以及 [terminal.js](../../web/terminal.js)。

## 相对路径与上下文

点击时创建不可变请求上下文：服务器 ID、配置修订、主机信任身份、连接 token、tmux socket/路径与 pane ID、原始目标。结果回填必须仍匹配上下文，不允许旧请求打开到新的服务器。

相对路径的基准按以下顺序确定：

1. 文件预览内的相对引用：当前远端文档所在目录。
2. 终端文件链接：用户为当前任务明确选定的项目根目录。
3. 未选定根目录时，tmux 查询当前目标 pane 的 `pane_current_path`，仅作为候选基准；显示解析后的路径，允许“更改基准目录”。普通 SSH 没有 tmux pane 时，首次提示指定目录，可使用登录用户 HOME 作为可见建议。

不使用新开的 exec shell 的 `pwd` 假装终端当前目录；Agent 工具目录可能与 pane 的工作目录不同。首版通过明确基准解决歧义，不接管 Agent 协议、不搜索整台服务器找同名文件。

目录选择只在有歧义或当前基准不可用时出现，支持输入目录并做 SFTP 验证，不需要先实现完整文件管理器。用户选择按服务器配置修订 + pane 缓存在当前终端生命周期内；不额外上传或跨服务器共享。

读取前按远端规则展开 HOME、合并和规范化路径；URI 仅解码一次，拒绝 NUL/控制字符。SFTP realpath 的结果作为显示与资源定位依据，stat 确认为普通文件后读取，目录、FIFO、设备等拒绝。不将链接内容拼入 shell 命令；查询 tmux 工作目录使用现有转义/目标验证方式。

SFTP 若被 chroot，文件命名空间可能与 shell 路径不同。返回明确的“文件不存在或 SFTP 路径不可访问”，允许用户调整目录；首版不自动猜测 chroot 映射，也不改用 shell 执行链接。

## 远端读取与取消

为 `SshClient` 增加有明确所有权的只读文件传输句柄：连接内打开 SFTP，提供 stat / realpath / 有界流读取 / cancel / close，纳入连接关闭清理。现有 `exec()` 限 512 KiB UTF-8 文本，不用于图片下载。

- 一个预览会话至多一个 SFTP 通道、一个传输 worker，关联资源排队；ChannelSftp 不跨线程并发调用。预览关闭即释放，不放进 SSH 空闲保活池。
- 通道使用当前已认证 Session，继承用户、跳板及主机验证；不重新握手，不弹第二轮指纹，也不借用任意空闲服务器连接。
- SFTP 开通本身仍有 subsystem 初始化往返，读取仍需网络时间；“复用 SSH”不等于零延迟。部分服务器限制通道数或禁用 SFTP，显示原因，不关闭终端。
- IO 在专用后台 dispatcher/executor，不进入 `TerminalWriteQueue`，不占终端输出读取线程。共享 TCP 带宽仍可能影响终端，需要通过限并发、上限和用户取消控制，不承诺完全无影响。
- 单次取消仅断开它拥有的 SFTP 通道，不调用整个 `SshClient.cancel()`，不以修改 Session 全局 socket timeout 实现文件超时。连接断开则统一取消其全部预览资源。
- 长时间无进度/总时限由传输任务自己的 watchdog 触发关闭通道；关闭通道须能解除阻塞读取，在集成测试中验证。
- 首版 SFTP 不可用就提示。二进制 exec 读取作为后续兼容项，不为它新增远端命令注入面或重新登录链。

本地临时文件位于 `cacheDir/preview/<随机会话ID>/`，使用生成的文件名和单独的远端路径映射，不把远端绝对路径当成本地拼接路径。不申请外部存储权限、不建立永久模型式下载目录。

## 渲染与关联资源

预览 WebView 与终端 WebView 完全分离，绝不注入 `NativeTerminal` 或其他可操作 SSH 的 JavascriptInterface。外链通过原生 WebViewClient 路由。

| 渲染器 | 实现约束 |
| --- | --- |
| Markdown | 本地固定版本 Marked + DOMPurify；原始 Markdown 作为数据传入，不拼接可执行脚本。受信本地模板运行渲染，禁用文档中的脚本/事件属性、iframe、表单等主动内容 |
| 静态 HTML | JavaScript 关闭；限制 meta refresh、iframe、object/embed、表单提交、弹窗和下载等行为；保留静态布局和 CSS，不能把“关闭 JS”视为已阻止全部导航与网络 |
| 图片 | BitmapFactory 先读尺寸，后台采样解码；Compose 管理缩放、拖动、边界、双击与释放；有界解码，不把压缩文件大小当内存大小 |

使用独立的虚拟 HTTPS origin / 每个预览会话 token，通过受限本地资源路由提供文件，不启用 `file://` 通用访问或 content 访问。未知请求一律拦截，不能在 loader miss 时回落到公网。

相对图片、CSS、子文档按远端文档目录解释，转换为受控资源 URL；不递归下载项目。初始自动资源范围为已选项目根目录，未指定时为文档父目录。`..` 和符号链接按规范化后的路径检查；越过范围的自动资源不读取，显示缺失资源提示，允许用户扩大基准范围。主动点击其他文件可转为新的主文档并显示实际目标。

远端路径检查属于当前 SSH 权限下的资源约束，不宣称 SFTP 的 realpath+get 可以原子防止服务器上并发重命名或符号链接替换。不能让远端页面获得通用文件读取桥接；不向公网自动发送页面内容或文件资源。

不自动下载远程 HTTP(S) 图片、CSS、字体或 CDN。CSP + 原生请求拦截双重约束；data/blob、CSS import、srcset、协议相对 URL、重定向等不能绕过关联资源策略。静态页面依赖脚本或远程资源时显示明确的受限预览说明。纯文本字符集首版 UTF-8，支持 BOM；无法可靠解码时报错，不把乱码当成功。

依据：[Android WebView 本地内容与资源路由](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)、[Android 大图采样](https://developer.android.com/topic/performance/graphics/load-bitmap)、[Compose 多点手势](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/multi-touch)。

## 外部链接与生命周期

HTTP(S) 只在用户明确激活时交给系统 ACTION_VIEW；缺少可用浏览器时提示并提供复制，不崩溃。预览资源请求、重定向、自动刷新不能自动弹系统浏览器。

`localhost`、`127.0.0.1`、`::1` 仍指手机本机。首次遇到此类外链时解释地址含义并允许复制/继续，不暗中打开 SSH 端口转发。

当前 MainActivity.onStop 会断开 SSH 并关闭空闲链；跳到完整外部浏览器可能触发该策略。本功能不顺带改变后台连接策略，返回后按现有连接流程恢复。应用内预览 Dialog 不会因自身打开就触发 Activity.onStop。

旋转、主题或语言重建按现有 Activity 生命周期处理：不持久化整个 WebView/位图/活连接，不回放旧文件读取，清理旧预览会话；如果要跨重建恢复预览，后续仅恢复路径并由用户重试。

## 初始资源预算

以下是实施起点，待真机测试调整；都按实际流量/解码量执行，不能只信 stat 或 Content-Length。

| 项目 | 初始上限 |
| --- | --- |
| 单个 Markdown / HTML | 2 MiB |
| 单个 CSS | 512 KiB；本地依赖共同受资源数量与总字节预算约束，缓存去重 |
| 单个图片压缩文件 | 20 MiB |
| 图片尺寸与解码 | 原图最多 100 MP、单边 32768；解码输出最多 8 MP，ARGB_8888 约 32 MiB，按设备可用内存进一步下调 |
| 一个预览会话的远端临时数据 | 合计 50 MiB，关联资源最多 32 个，含文档导航历史 |
| 全应用预览缓存 | 100 MiB，最多一个活跃面板；超限先淘汰不再显示的资源，仍超限就停止读取并提示 |
| 文件传输 | 开通通道 10 秒，无进度 10 秒，单文件总计 30 秒；可取消并显式重试 |
| 导航历史 | 最多 10 个文件，按需重读，不将全部已解码图片留在内存 |

关闭即清理；失败及取消清理半文件；进程启动清理上次遗留的 preview 会话目录。缓存是可丢弃数据，读取时应处理系统主动回收。并发删除与仍在读取的 WebView 资源通过预览会话所有权统一协调。

基础新增 APK 以 1 MB 内为预算目标，需同一提交、同构建配置前后对照验证。已有调研测得 Marked + DOMPurify 部署 JS 合计约 79 KB 原始文件，不等于完整功能或 APK 增量。固定版本、哈希、许可证，随包加载，不使用运行时 CDN。

## 模块与实施顺序

名称为建议，实施时允许按当前目录结构调整。

| 阶段 | 主要交付 | 完成门槛 |
| --- | --- | --- |
| P0：链接与通道验证 | `web/terminal-links.js` 小验证、SFTP 取消验证；覆盖现有触摸层和远端鼠标模式 | OSC 8 标签取到真实地址；普通路径命中；点击不产生远端输入；单独取消不影响 shell/Agent |
| P1：路径与读取 | core 中 `RemoteFileAccess`、路径解析与预算；app 中 `PreviewController` 管理不可变上下文和临时会话 | 绝对/相对/HOME、同名歧义、缺失/无权限/禁用 SFTP、跳板、断线、超限均有可验证结果 |
| P2：预览面板 | `FilePreviewDialog`、`FilePreviewWebView`、`ImagePreview`；Markdown/HTML 本地资源与导航 | 三类文件可浏览，外链正确跳转，加载和取消可见，清理和原生输入隔离成立 |
| P3：移动端与构建复核 | 触摸、IME、真机 WebView、性能、标准/语音变体与许可证 | 回归清单通过，产出实际 APK 增量、内存与传输日志结果，再进入发布流程 |

`MainActivity` 仅接收带 token 的打开请求、管理面板显示和焦点；具体路径、传输、渲染拆出。`TerminalView` 桥接新增单一受限的链接请求，不复用 input 发送文件路径；`web/bundle.mjs` 同步新增资源到 app assets，避免只改 web 源码导致 APK 行为未更新。

## 可行性复审结果

| 审查项 | 当前证据与判断 | 实施前/中剩余验证 |
| --- | --- | --- |
| 安装包依赖 | Compose、AndroidX WebKit、JSch 均已存在；基础渲染不需要新原生运行库 | 选定 JS 的旧 WebView 语法兼容、许可证和实际 APK delta |
| OSC 8 被触摸层遮挡 | 当前 xterm 公开 linkHandler/hover 提供目标与 range，可通过 screen 命中探测接入 | 真机 Android、重绘/换行/滚屏/IME 位移、不会误发鼠标、重复点击 |
| 相对路径 | 可以查 tmux pane 路径，但无法普遍知道 Agent 工具目录 | 明确项目根目录与错误后改目录的交互，不承诺自动猜对 |
| SSH 复用 | 当前 SshClient 持有认证 Session；JSch 依赖自带 SFTP | 新传输所有权、取消可解除阻塞、通道上限、被禁用/chroot 的服务器 |
| 文件读取不阻塞终端 | 可用独立通道/IO worker，不进入现有终端写队列 | 同一 TCP 链共享带宽，需弱网及大图读取时的输入响应测试 |
| 远端页面隔离 | 可以新建无桥接 WebView，已有资产 loader 模式可参考 | 必须实测 CSS/图片/重定向等所有请求均受限，不能仅靠 JS off |
| 图片资源 | 系统解码 + Compose 足够完成截图的缩放拖动 | 有界采样、EXIF 方向、透明图、低内存和反复开关；原图细节缩放有采样限制 |
| 生命周期 | 当前 onStop 策略明确；Dialog 本身不需后台 Activity | 外部浏览器返回、重建、切服务器、加载中关闭和缓存回收 |

结论：首版范围可实施，整体复杂度中等；主要风险集中在触摸与链接命中、相对目录、取消与 WebView 资源边界。没有发现必须引入重型依赖或新增服务器服务的阻碍。P0 是正式实施的首个验收关口，不能将纸面支持等同于已完成的功能。

## 2026-11-01：适配重构后的 UI

复审参照：`2536851`（0.9.3-rc.3）的 `MainActivity.kt`、`ServerHome.kt`、`TerminalKeys.kt`、`UiComponents.kt`、`AppAppearance.kt`，以及方案 A 第二版的首页动作面板和编辑卡片设计图。设计图用于视觉参考，具体间距、字号和状态行为以当前生产代码为准。本节约束已纳入本轮基础实现，验证范围见实现记录。

结论：本次重构没有阻碍独立 WebView + 同 SSH 链 SFTP 读取，安装包依赖判断不变；需要重点适配弹层、焦点、终端尺寸和隐私显示，不能直接套通用弹窗后认为交互已经一致。

### 视觉与容器

- 沿用当前主题的 background / surface / surfaceVariant / primary / onSurfaceVariant、线性图标和 24–28dp 圆角，不固定为蓝色或深色；六套主题和浅深模式均适配。标题区沿用 `SheetHeader` 的层级，文件名为主、服务器与路径为次，返回/关闭采用现有 `AppIconButton`。隐私显示开启时服务器标识使用现有脱敏规则；完整路径不默认暴露在首页或系统通知。
- 文档主体接近全屏，窄屏保留约 8–12dp 边距、宽屏限制可读宽度；标题操作固定，正文独立滚动。图片主体使用主题背景，缩放时只由图片手势层处理，关闭入口始终可见。
- 单独实现 `FilePreviewDialog/Surface`，可以复用标题、按钮、错误提示等内部组件，但不直接把 WebView/图片嵌入当前 `AppDialog` 的外层 verticalScroll，也不直接用 `AppSheet` 的下滑关闭。现有 AppDialog 固定最大宽 460dp/高 640dp 且含外层滚动；AppSheet 是带拖拽的 ModalBottomSheet，都会限制阅读空间或与文档滚动、图片拖动争手势。
- 首版不提供“拖文档/拖图片即可关闭”，通过固定关闭按钮和返回键退出。弹层进出用约 150–200ms 的轻量透明度/位移过渡，尊重系统动画缩放；不新增模糊效果或空闲动画。

### 与现有终端、编辑卡片和语音的关系

1. MainActivity 中终端持续挂载，ServerHome 在其上显示。预览仅能从当前前台终端打开：校验 `!showConfig`、连接 token、目标身份及当前 modal 状态，首页隐藏着的终端不得响应迟到的打开请求。
2. 预览、工具面板、快捷回复、编辑卡片、指纹验证和语音录音/转写弹层互斥。已经有编辑、语音或指纹流程时，底层终端不接收点击；不为了显示预览强制取消录音、提交草稿或覆盖已有编辑卡片。
3. 进入预览时按当前工具/编辑面板的焦点退出方式处理 DirectTerminalInput、IME 和粘滞修饰键，禁止未确认组词或旧 InputConnection 回调落到远端。预览内选字、复制、搜索/路径输入（如后续提供）不得成为终端输入。
4. 预览使用独立 Dialog Window，不改终端顶栏、底栏高度或键盘避让算法；打开、关闭、文档键盘和横竖屏分别检查 xterm 行列、viewport 和 PTY resize。已有 `keyboardFreeHeight` / 固定网格规则继续生效，不能为新增预览恢复终端随 IME 缩小的旧行为。
5. 返回键处理顺序按实际前台窗口确定：先关闭预览中的 IME，再退文档历史，再关闭预览；不同时触发终端 `home()`。返回首页、换目标时清理预览及请求，不能让其悬在新的服务器之上。
6. 预览窗口继承当前 FLAG_SECURE / 隐私保护策略，支持前后台敏感内容遮蔽；不能只给 Activity 配置而漏掉 Dialog 的 Window。不要调用连接验证弹窗的专有关闭流程，避免误触发首页刷新或信任状态修改。
7. SFTP 仍由当前终端连接单独持有传输通道，不进入首页 refresh job、连接移交或空闲链池；打开预览不触发全局刷新、重连或主机再验证。断线保留已加载内容的规则与旧 token 校验保持本计划原约定。

### 需要增加的联动验收

- 深浅主题、长路径、大字体、横屏、图片缩放、文档滚动：没有两层纵向滚动或下滑误关窗，关闭/返回不被内容盖住。
- 打开/关闭预览 10 次，期间文档滚动、复制、输入法开关，终端输出继续更新，PTY 不因开关面板 resize；关闭后直接输入和 Ctrl/Shift/Alt 不丢失、不重放旧回调。
- 编辑卡片或语音录音/转写存在时不叠开预览；后台返回、首页、目标切换及指纹弹窗出现时，不留下错误的弹层/输入焦点。
- 实际 Android WebView 内测试独立资源 origin、渲染及请求拦截；桌面 Chromium 和离线合成图不能替代此验收。

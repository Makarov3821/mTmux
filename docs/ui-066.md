# 0.6.6-dev：终端右侧中文裁切

## 复现与定位

用户反馈手机行尾中文只显示半个字或几个像素，而电脑查看同一 tmux 正常。Android 15 模拟器、WebView 124.0.6367.219、默认系统缩放下复现。

纯汉字重复和整行 ASCII 没有暴露问题；加入中文全角标点后稳定失败。字号 14、37 列、终端绘制宽度 314 CSS px 时，包含 `，。！：` 的混合行实际文字边界到达 341.1875 px，超过约 27 px。普通和粗体中文均受影响。

xterm 5.5 的 DOM 渲染器通过重复同一字符测量并缓存字宽，再用 letter-spacing 对齐网格。浏览器对连续中文标点的上下文压缩会使重复标点样本和实际混合句子的宽度不一致，误差积累到右端后被容器裁切。复制文本仍完整，因为终端缓冲区没有丢失这些字符。

真实 OpenSSH + tmux 验证：xterm 和 tmux 客户端均为 37×34，pane 为 37×33（状态栏占一行）。列数一致，键盘开合不改变网格尺寸；本次复现的原因在手机文字绘制。

## 修复

在终端根容器设置 `text-spacing-trim: space-all`，让测量元素与实际行统一保留标点字面间距。无需修改 xterm 依赖源码，随本地终端资产打包。没有缩减列数、增大边距或改变 tmux 配置。

相同 Android 测例修复后行尾边界为 314.0234375 px，恢复至网格宽度；13、14、17、20 四种字号均通过。
